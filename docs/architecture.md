# 概念設計

状態：概念上の責務を整理したもの。技術スタックと具体的な実装構成は未決定。

## この文書の範囲

[全体企画書](product.md) の体験を実装する際に、分けて考える責務を示します。以下の区分は、ライブラリ、クラス、プロセス、サーバーなどの構成を指定するものではありません。

## 責務の分離

| 責務 | 扱う内容 | 関連する仕様 |
| --- | --- | --- |
| 表示と入力 | 2Dドット絵のマップ、人物、会話、選択肢、状態や結果を表示し、操作を受け取る | [遊びの進行](features/gameplay.md) |
| 探索と自由行動 | マップ上の移動や行動を扱い、イベントの発生につなげる | [遊びの進行](features/gameplay.md) |
| 人生の進行 | 年代の移行と生活の変化を扱う | [遊びの進行](features/gameplay.md) |
| イベントの進行 | 決定済みの発生条件、選択肢、結果、影響、分岐に従って出来事を進める | [イベント共通仕様](features/events.md) |
| プレイヤーの状態 | 年齢、能力、嗜好、資産、交友、職歴などと、選択による変化・長期的な影響を扱う | [プレイヤーの状態](features/player-state.md) |
| ゲーム内容の定義 | 採用したイベント、マップ、生活上の行動などの内容を管理する | [イベント詳細の管理](events/README.md) |

イベントの具体的な内容と、それを進める共通の仕組みを分けて考えます。年代や生活内容を増やす際も、表示・操作、イベントの進行、状態への影響をそれぞれ確認できるようにします。定義データの形式や置き場所は未決定です。

## データと状態の扱い

プレイヤーの現在の状態と、採用したイベントなどの内容の定義を区別します。選択による結果を状態へ反映し、後の生活やイベントで参照することで、長期的な影響を扱います。

どの履歴を保持するか、影響をいつ反映するか、発生条件をどう判定するかは今後決めます。各パラメータの初期値、範囲、変化量、計算式も未決定です。通貨は円とします。

[イベント候補](events/security-events.md) や [未採用の演出案](ideas/time-pressure.md) は、実行するゲーム内容の定義ではありません。採用と詳細仕様を決める前に、そのまま実装対象として取り込みません。

## 責務間のやり取り

概念上は、次の流れを扱います。具体的なAPIやデータ構造は未定です。

1. プレイヤーの移動、自由行動、イベントでの選択を受け取る。
2. 現在の年齢や状態と、決定済みの行動・イベントの条件を参照する。
3. 選択の結果と影響を状態に反映し、後の進行や分岐につなげる。
4. 状況、結果、状態の変化をプレイヤーに伝える。

人生の時間が進む契機や速度、マップの接続、イベント発生の判定順、結果の表示方法は、この流れだけでは確定しません。

## 技術選定で今後決めること

- 対応環境、開発言語、ゲームエンジンや描画ライブラリ。
- マップ、イベント、プレイヤー状態のデータ形式と管理方式。
- 保存・再開の要否と方式、通信やサーバーの要否。
- 実装の分割、責務間のインターフェース、検証に使うツール。

採用する技術とその理由は、決定時に [判断の記録](decisions/README.md) に残します。素材用の既存フォルダから技術やデータ形式を推定しません。

## 検証方針

実装する範囲の [機能仕様と受け入れ条件](features/README.md) を先に具体化します。探索・選択・状態変化の流れ、個別イベントの条件と分岐、選択が後の人生へ与える影響を確認します。

対象ユーザーが状況と結果を理解できるかは、ゲーム体験として検証します。テスト手法や具体的な評価基準は、実装範囲と技術選定に合わせて決めます。
