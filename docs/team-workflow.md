# チーム開発の運用ルール（提案／要合意）

複数人と AI エージェントが並行して開発するときに、同じファイルを重複して編集しないための運用を定めます。経緯と受け入れ条件は [Issue #43](https://github.com/kame447/gmo-security-life-game/issues/43) で管理します。

現在は **警告モード**（`warn`）で運用し、チームの合意後に **強制モード**（`enforce`）へ切り替えます。

## 基本ルール

1. **作業範囲の宣言**：作業を始めたら、コードを書く前に `main` 宛ての Draft PR を作り、本文の `scope` ブロックに編集するパスを書く。
2. **占有範囲**：オープンな PR の `scope` と、その PR で実際に変更したファイルを、その作業の占有範囲とみなす。`scope` を宣言していない PR は、変更したファイルだけを占有範囲とみなす。PR のないリモートブランチは占有範囲として扱わないが、確認コマンドは重複として表示する。
3. **先着優先**：範囲が重なった場合は、先に作成された PR を優先する。後から作業する側が担当者と調整し、範囲を分けるか、作業の順番を決める。
4. **範囲の変更**：作業中に範囲が広がったら、編集する前に PR 本文の `scope` を更新する。
5. **解放**：PR をマージまたはクローズすると、占有範囲は自動的に解放される。中断する作業は Draft PR のまま放置せずに閉じる。

`scope` ブロックの書き方：

````markdown
```scope
# 1行に1パターン。# 以降はコメント
game/src/phone/          # 末尾が / のディレクトリは配下すべて
docs/features/phone.md
game/tests/phone-*.test.ts
```
````

パターンの `*` は `/` を含まない任意の文字列、`**` は `/` を含む任意の文字列に一致します。

## 共有ファイル

多くの機能が同時に変更する入口・目次のファイルは、排他にすると作業が止まるため「共有ファイル」として扱います。一覧は `.github/scope-guard.json` の `shared` にあります。

- 共有ファイルは他の作業と同時に変更してよいが、変更は最小限にし、PR 本文に変更箇所と理由を書く。
- 機能の本体は共有ファイルに書かず、機能ごとのファイルに分ける。
- 共有ファイルの追加・削除は、このファイルと同様に PR でチームの合意を取る。

## チェックの仕組み

判定ロジックは `scripts/scope-guard/` に一つだけ置き、以下の各段階から共通に呼び出します。GitHub の情報は `gh` CLI で取得します。

| 段階 | 実行方法 | 対象 | 警告モード | 強制モード |
|---|---|---|---|---|
| 編集前の確認 | `node scripts/scope-guard/cli.mjs check <path...>` | 全ツール（AGENTS.md で実行を義務付け） | 重複を表示 | 同左 |
| 一覧の確認 | `node scripts/scope-guard/cli.mjs status` | 全ツール | 全作業の占有範囲と、重複の多いパスを表示 | 同左 |
| 編集時 | Claude Code の PreToolUse フック（`.claude/settings.json`） | Claude Code | 利用者に確認を求める | 編集を拒否する |
| コミット時 | Git の pre-commit フック（`.githooks/pre-commit`） | Codex を含む全ツール | 重複を表示 | コミットを中止する |
| PR | GitHub Actions（`.github/workflows/scope-guard.yml`） | すべての PR | 警告として表示 | チェックを失敗させる |

判定の区分：

- **重複**：他の人の作業が占有しているファイル。編集前に調整が必要。
- **共有**：共有ファイル。同時編集を許可し、PR に記載する。
- **自分**：同じ作者の別の作業と重なるファイル。参考として表示し、マージの順番に注意する。

チェックに必要な `gh` の認証やネットワークが使えない場合、編集時とコミット時のチェックは作業を止めずに続行します。

## 初回の設定（各自・各クローン）

```sh
gh auth login                           # 未認証の場合のみ
git config core.hooksPath .githooks     # pre-commit フックを有効化
```

`core.hooksPath` を設定すると `.git/hooks/` の既存フックは使われなくなります。独自のフックがある場合は `.githooks/` へ移してください。Claude Code のフックは、リポジトリを開くと `.claude/settings.json` から自動で読み込まれます。

## 担当領域（案・要合意）

主担当は、その領域の PR のレビュー窓口と、範囲が重なったときの調整役です。主担当以外が編集してはいけないという意味ではありません。合意した内容は、後で `.github/CODEOWNERS` に反映し、レビュー依頼を自動化します。

| 領域 | 主なパス | 主担当 |
|---|---|---|
| インフラ・CI・開発運用 | `infra/`、`.github/`、`scripts/scope-guard/` | misanga1225 |
| 生活 UI（インベントリ・買い物・スマホ） | `game/src/ui/`、`game/src/phone/`、`game/src/shop/` など | 未定（i2rin・haRusuZu41・kame447 で要調整） |
| マップ・探索 | `game/src/world/`、`game/src/render/` など | 未定 |
| エディタ | `game/src/editor*/`、`game/scripts/editor.mjs` など | 未定 |
| 企画・仕様文書 | `docs/product.md`、`docs/features/`、`docs/events/` | 未定 |
