# ステージごとの出来事の案（意見募集）

状態：提案・意見募集中（未採用）。ここに書いた出来事・配置・選択肢はすべて叩き台で、採用・実装の決定ではない。
関連：[ストーリーの流れ](../features/story.md)（合意待ち）、[セキュリティイベント候補](security-events.md)、[イベント共通仕様](../features/events.md)、Issue #18

[ストーリーの流れ](../features/story.md) の提案では、序章のあと「中学 → 高校 → …」とステージを進め、各ステージで強制イベント（必ず経験する）と任意イベント（見つけた分だけ経験する）を起こす。仕組みは試作（PR #77）で動いているが、**各ステージで何が起きるか（中身）はまだ決まっていない**。この文書は、その中身をチームで決めるための叩き台である。案・反対・追加は Issue のコメントで募る。

## 前提（既存の文書で決まっている・提案されていること）

- 日常イベントが中心で、日常：セキュリティはおおむね 7:3〜6:4（[全体企画書](../product.md)）。ステージ単位でも目安とする（[ストーリーの流れ](../features/story.md)）。
- 強制イベントは結果にかかわらず経験すれば達成とし、行き止まりにしない。正しいセキュリティ判断や被害の回避を達成条件にしない。
- 危険な選択が必ず被害になるわけではない。結果は所持金・能力・交友・後の分岐に反映する（[イベント共通仕様](../features/events.md)）。
- セキュリティイベントだけに目印を付けない。日常の行動（買い物・SNS・連絡など）の中で自然に出会う。
- [SEC-001〜015](security-events.md) は全件が採用未決定・年代未分類。下の「配置の例」は議論のための例で、年代を決めるものではない。

## 決めたいこと（意見がほしい点）

1. **ステージの区切り**：中学・高校の後をどう区切るか（例：大学／専門／就職で分岐 → 社会人 → 結婚・子育て → 中年 → 老後）。全部でいくつにするか。
2. **各ステージの強制イベント**：そのステージを代表する出来事を何件・何にするか（下の案から選ぶ／足す／消す）。
3. **任意イベント**：町のどこで、誰と、どんな出来事を起こすか。1ステージに何件くらい置くか。
4. **セキュリティイベントの配置**：SEC-001〜015 をどのステージに置くか。新しい題材を足すか。
5. **ステージをまたぐつながり**：前のステージの選択が後で効く出来事（例：中学で公開した写真が高校で問題になる）をどこまで作るか。
6. **入れたくない題材**：対象（セキュリティ初心者を含む一般の人）に合わない、重すぎる題材はあるか。

## 町で使える場所・人（2026-11 時点の試作マップ）

自宅（1階・2階）、学校（教室・体育館）、公園、駅（隣町へ電車で移動）、商店街（やおや・ほんや・だがしや・パンや・きっさてん・くすりや）、コンビニ。人物は家族（母）、先生、同級生、友達、店員、駅員など。スマホにはチャット・メール（PR #74）・ウェブ検索（PR #80）が入る予定。

場所や人が足りない出来事は、マップ・NPC の追加が必要になる。

## 中学（案）

いま試作に入っている仮の中身：入学式（強制・時刻）、部活を決める（強制・教室に入ったとき）、期末テスト（強制・時刻）。序章で自転車購入（SEC-002）を経験済み。

### 強制イベントの案

| 案 | きっかけ | 選択肢の例 | 影響の例 |
|---|---|---|---|
| 入学式（試作済み） | ステージ開始 | なし（導入） | — |
| 部活を決める（試作済み） | 教室に入る | 運動部／文化部／帰宅部 | 体力・交友、放課後の自由時間 |
| 期末テスト（試作済み） | 時刻 | こつこつ勉強／一夜漬け | 学力 |
| 修学旅行の班決め・写真 | 時刻 | 誰と班になるか、撮った写真をどうするか | 交友。SEC-003（無断投稿）につなげる例 |

### 任意イベントの案

日常：
- だがしやで友達とおやつを分ける／分けない（交友）
- ほんやで参考書かマンガか（学力・所持金）
- 家の手伝いでお小遣い（所持金）
- 公園で年下の子の遊び相手（交友）

セキュリティ（配置の例）：
- SEC-011 無料アプリの過剰な権限要求：友達に勧められたゲームアプリが連絡先・位置情報を求める
- SEC-003 友達が写真を無断でネットに投稿：修学旅行・部活の写真
- 新しい案：クラスのチャットに回ってくるチェーンメッセージ（「回さないと不幸に」「拡散希望」の誤情報）
- 新しい案：オンラインゲームで知らない人から「アイテムあげるからIDとパスワード教えて」

## 高校（案）

いま試作に入っている仮の中身：入学式（強制）、文化祭の出し物（強制・委員長からメール）、進路の相談（強制）。

### 強制イベントの案

| 案 | きっかけ | 選択肢の例 | 影響の例 |
|---|---|---|---|
| 入学式（試作済み） | ステージ開始 | なし | — |
| 文化祭の出し物（試作済み） | 時刻（メール） | 喫茶店／劇／任せる | 交友 |
| 初めてのアルバイト | 時刻または店に入る | コンビニ／きっさてん／しない | 所持金・経験。働き先での出来事につなげる |
| 進路の相談（試作済み） | 時刻 | 進学／就職 | 次のステージの分岐（フラグ） |

### 任意イベントの案

日常：
- 電車で隣町へ出かける（交友・所持金）
- アルバイト先での接客・失敗（経験・所持金）
- 友達の誕生日プレゼントを選ぶ（交友・所持金）
- 恋愛のきっかけ（扱うか自体を決めたい）

セキュリティ（配置の例）：
- SEC-010 SNSへの個人情報の載せすぎ：誕生日・ペットの名前の投稿 → 後のステージで「秘密の質問」を突破される
- SEC-012 写真の公開範囲の誤設定：文化祭の写真
- SEC-004 フリーWi-FiとHTTP通信：きっさてん・駅のフリーWi-Fi
- SEC-009 アップデートの先延ばし：スマホの通知
- SEC-005 reCAPTCHA：チケット予約サイトなど（題材の具体化が必要）

## 決まったら

採用した出来事は、個別のイベント文書（状況・発生条件・選択肢・結果・状態への影響・分岐）に起こし、[ストーリーの流れ](../features/story.md) のステージ一覧と実装（`game/src/story/`）に反映する。SEC 候補の年代を決めた場合は [セキュリティイベント候補](security-events.md) も更新する。
