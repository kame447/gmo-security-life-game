# 0003: 幼少期マップのプロトタイプを Canvas 2D と独自 TypeScript データで検証する

記録日：2026-11-12

状態：プロトタイプでの提案／要検証。本採用の決定ではありません。

関連：[Issue #7](https://github.com/kame447/gmo-security-life-game/issues/7)、[マップ分割構造と制作工程](map-structure-and-pipeline.md)

## 背景

道路でつながる住宅街・学校・駅・商店街・川沿い公園を歩き、自宅と教室へ出入りできる幼少期の探索プロトタイプを作ります。描画と移動・データ検証を分離し、町の接続、衝突判定、出入口の往復を確認できることを優先します。

## 今回試す方針と理由

- 描画はブラウザ標準の Canvas 2D API、開発・ビルドは Vite、実装は TypeScript とします。ゲームエンジンとランタイム依存パッケージは追加しません。依存を少なく保ち、描画処理と移動・衝突処理の境界を自分たちで確認できる構成です。
- マップは `game/src/world/` の独自 TypeScript データで定義し、型は `game/src/core/types.ts`、座標変換は `game/src/core/coords.ts` に集約します。地面・配置物・施設・出入口・インタラクション・年代差分を画像から分け、DOM に依存しない検証と Node 上のテストで扱います。
- 地面をチャンク単位でキャッシュし、可視範囲を描画します。建物・家具・キャラクターなどのスプライトもコードで生成します。参考画像は平面配置・配色の検討用であり、ランタイムでは読み込みません。

## 今回採らなかった候補

- **Phaser**：今回の範囲では、シーン管理や物理処理を外部エンジンに委ねず、小さい探索処理として実装します。エンジンへのランタイム依存とそのAPIへの変換を増やさずにデータ契約を検証するため、今回は導入しません。
- **PixiJS**：今回は Canvas 2D の描画でプロトタイプを作り、別の描画ライブラリへの依存を増やさない方針とします。描画性能の優劣を確認した結果ではありません。
- **Tiled**：今回は TypeScript のデータ定義を直接テストできる構成にし、エディターの出力と独自の施設・出入口・年代差分の契約を対応付ける変換工程を設けません。今後、手作業での配置編集が必要になった際は再検討します。

これらを不適切と判断したわけではありません。制作規模、編集体験、性能の計測結果に応じて再比較します。

## プロトタイプでの提案値（要検証）

| 項目 | 今回の仮置き |
| --- | --- |
| タイル寸法 | 16×16px |
| チャンク寸法 | 16×16タイル（256×256px） |
| 屋外エリア `town-main` | 128×80タイル（8×5チャンク） |
| 自宅／教室 | 16×12／18×12タイル |
| コンビニ（追加検証） | 14×10タイル |
| 座標系 | 北西原点、東が +X、南が +Y |
| 移動方式 | ピクセル単位の4方向移動、斜め移動なし |
| 歩行／走行 | 72／128px毎秒 |
| 表示 | 整数倍ズーム、画像補間なし |
| 地面チャンクのキャッシュ上限 | 24チャンク |

速度や町の広さは操作感と移動負担を確認するための提案値です。画面解像度、対象端末・ブラウザの基準、性能・容量の合格閾値は未決定です。初稿時点では性能は未計測で、FPS、フレーム時間、メモリ消費、初回ロード時間の達成値はありませんでした。その後の計測状況は [プロトタイプの検証記録](../../game/README.md) に追記し、技術選定の本採用や性能達成とは区別します。

## 範囲と見直し条件

全年代は未実装です。年代差分は型と `childhood` のデータのみであり、年代進行、人生の時間進行、イベントの条件評価・選択肢・結果は今回の対象外です。

追加の検証範囲として、主人公の外見選択、コンビニ内部への出入り、屋内の壁の外側を黒くする表示を扱います。外見の選択肢・保存後の扱い・描画の詳細もプロトタイプでの提案／要検証であり、本採用の決定ではありません。詳細は [マップと探索](../features/map.md) に追記します。

町の規模や施設・年代差分の増加で編集負担が大きくなった場合、または対象端末での性能計測で問題が確認された場合は、描画ライブラリ、データ形式・編集ツール、タイル・チャンク寸法を見直します。
