# 0012: 実行中のエリアからミニマップを生成する（提案／要検証）

## 背景

Issue #15 は、現在地に追従する周辺地図と、同じエリアの全体地図を求めている。手書き画像を別に管理すると、実際の道路・建物・通行可能範囲や出入口と地図が食い違う。

## 今回の方針

- `AreaRuntime` の地面タイル、衝突索引、建物の占有範囲、有効な出入口から、タイル単位の概略地図を作る。ゲームのデータを変更せず、個別の町の座標を複製しない。
- 建物の代表色は `render/building-colors.ts` の関数に集約し、スプライトの屋根・主な上面と地図の建物セルが同じ関数を使う。住宅の style 別屋根、店舗の屋根／上面、学校・体育館・駅・公園の東屋を含め、地図側に施設IDと色の対応表を持たない。地形・通行可能範囲・有効な出入口の色は従来通りとする。
- 施設の名称・種別は `world/town.ts` の `FACILITIES` を正本とし、現在のエリアと同じ `areaId` の施設を配置物の `facilityId` に結び付ける。自宅・学校・駅・公園・7種類の商店に加え、実在する体育館に名称・種別と参照IDを補う。種別のない既存データには汎用の菱形記号を使い、IDや style から施設名を推測しない。
- 周辺図（192×128）は必要な小さな施設記号のみを表示し、全体図には記号と施設名を表示する。家・校舎・鉄道車両・木・本・パン等の異なる図形を使い、色だけに依存しない。名称は実表示の13pxを保ち、ラベル同士・施設記号・現在地に重ならない位置を探索し、施設との対応を引出線で示す。スマホでは全体図の縦方向の余白も用いて名称を分散する。
- 周辺表示は主人公の足元座標を中心に追従し、全体表示は現在エリア全体を縦横比を保って収める。どちらも現在地と向きを示す。
- 実行中のエリアオブジェクトごとに地図画像をキャッシュし、エリアの切替時は別の地図を使う。現行の実行時エリアは組立後に地形・衝突を変更しない。将来、同じオブジェクトを更新する機能を導入する場合はキャッシュ無効化が必要。
- 全体図は探索・会話・外見変更と排他的にし、開いている間はゲームの更新呼出しを止める。開閉時に押下中の移動入力を解除する。

## 制約と今後の確認

地図は占有タイルと通行可能範囲の概略であり、建物の立面や描画上の装飾まで再現しない。色・寸法・周辺範囲は試作値で、実画面の見やすさを確認する。未統合のバッグ・スマホ等との画面配置と入力の共存は、それらを統合した時点で確認する。

町の南側にある背景カフェには施設定義・固有名がなく、商店街のカフェと同じ施設とは見なさない。そこにも名称を付ける場合は、`FACILITIES` に独立した定義を足し、該当配置物に `facilityId` を付ける。病院・交番・銀行など未配置の候補施設は地図に追加しない。

検証は `tests/minimap.test.ts` と `tests/building-colors.test.ts` で色の共通出所、style による差、施設種別、屋内切替、画面寸法別のラベル配置を確認する。`scripts/e2e-minimap.mjs` でPC・スマホ縦横の開閉・追従・入力／更新停止・出入口遷移・名称描画を確認し、`scripts/shots-minimap.mjs` の比較画像はgit管理外の `game/test-results/minimap-compare/` に置く。
