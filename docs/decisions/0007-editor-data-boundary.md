# 0007: GUIの編集結果を限定したJSON差分として扱う

記録日：2026-11-13

状態：独立サンプルで試すプロトタイプ。既存マップの形式を置換する決定ではありません。

関連：[Issue #23](https://github.com/kame447/gmo-security-life-game/issues/23)、[編集基盤の仕様](../features/editor.md)、[マップと探索](../features/map.md)、[ゲームのモジュール構成](0004-game-module-structure.md)。

## 背景

現在の町・屋内と既存NPCはTypeScriptで生成します。GUIから座標等を編集するために手書き生成コードの文字列を置換すると、配置以外の処理や別担当の変更まで上書きするおそれがあります。マップGUIとNPC GUIは、描画・イベント実装を所有せずに同じ検証・差分適用を使える必要があります。

## 決定

- 安定IDで参照するエリア・施設・配置物・インタラクション・出入口を、画像やイベント分岐から独立した `EditorDocument` にまとめる。
- 既存の町・NPCを移行せず、`game/data/editor-prototype.json` 一つで編集→出力→適用→再読込→既存Gameでの利用を検証する。通常の `buildWorld()` は変更しない。
- 編集操作を追加・更新・移動・削除に限定し、エンティティ全体の変更前後と編集元文書を出力する。任意コード・ファイルパス・評価式は受け付けない。
- スナップショットは差分のサイズを増やすが、手修正や並行変更を衝突なく検出でき、ブラウザとNodeで同じ同期APIを使える。独自の短いハッシュで一致判定を省略しない。
- 配置の参照・衝突・強制遷移を含む到達性を、変更全体に対して検証する。関連する施設・出入口等の一括操作を可能にし、失敗時は入力を保つ。
- Undo/RedoはGUIに依存しない文書のスナップショットで扱い、画面の選択・パン等は別に保持する。
- 同じTypeScript検証をブラウザとNode.js 24のCLIで利用する。既存依存パッケージを増やさず、CLIはJSON一つへロック・一時ファイル・renameで適用する。

## 範囲と制約

タイル寸法16px、入力上限、サンプルの地形・施設・人物・台詞は確認用の仮置きです。全マップ・年代・キャラクター・イベントの正式仕様として採用しません。文書ID・開始点・カタログはv1では手編集と再読込で扱います。

既存の生成マップへの移行、外部アセット管理、スキーマ版の移行、差分サイズ削減、共同編集、シナリオ編集、GUIの個別機能は後続の設計・実装です。描画・衝突・出入口の仕様が変わる場合はランタイム変換と契約テストを一緒に更新します。
