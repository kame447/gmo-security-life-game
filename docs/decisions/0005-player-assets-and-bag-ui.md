# 0005: 資産の共通操作とバッグ画面の試作

記録日：2026-11-13

状態：実装方針。第二波の画面は試作／利用者レビュー前。見た目・カテゴリ・数値・操作を企画確定とみなさない。

関連：[Issue #20](https://github.com/kame447/gmo-security-life-game/issues/20)、[機能仕様](../features/inventory.md)、[モジュール構成](0004-game-module-structure.md)

## 背景

買い物・イベントから金額と所持品を同じ規則で扱い、支払だけ／取得だけの反映を防ぐ必要がある。旧PR #28のテキスト一覧は利用者にゲームUIとして不十分と判断され、未マージで取り下げられた。内部の計算・保存と画面を分け、別ブランチで画面を試作し直す。

## 方針

- `PlayerAssets` が整数の円・個数・上限を検証し、金額と品をまとめて置き換える。失敗時は全体を変えない。参照・保存にはコピーを返す。
- 既存キー・v1へ任意欄assetsを加える。対応形式では破損した欄だけ修復し、位置の破損で資産・外見を失わない。
- アイテム定義・仮の初期資金・価格を計算処理から分ける。価格は買い物側で持つ。
- バッグはポケット・アイコン付きスロット・選択と詳細・所持金・空状態を持たせ、資産の変更操作は置かない。画面の選択は保存しない。
- パネルがDOM・CSS・コード描画アイコンをマウントし、共通のModalPanelHostに登録する。共有ファイルの変更を起動時のimport・登録に抑え、他画面との排他を共通化する。
- 動作テストだけで視覚品質を合格にしない。デスクトップ・小画面の実ゲーム上の画像と操作結果を示し、利用者レビューを経てPRへ進む。

## 範囲外

マップ・NPC・外見・既存描画素材は変更しない。使用・譲渡・装備・売却の効果、在庫や経済バランス、年齢進行やクラウド同期は今回決めない。ポケット名・配色・アイコン・上限や初期資金は見直せる仮案とする。
