# 0010: headless ブラウザ E2E を CI で実行する

記録日：2026-11-13

状態：提案／要検証。実行時間とランナー上の安定性を確認して見直します。

## 背景

探索画面の操作や描画は DOM 非依存の単体テストだけでは確認できません。これまで Playwright の Chromium による機能 E2E は、ブラウザを起動できる環境の担当者が別途実行していました。機能ごとの E2E スクリプトも順次追加されるため、プルリクエストで継続的に実行できる入口を用意します。

## 今回試す方針

- `.github/workflows/e2e.yml` を既存 CI と独立させ、`game/**` またはこの workflow の変更を含むプルリクエストと main への push で実行します。
- Ubuntu ランナーに Node.js 24 と npm の依存、Playwright Chromium およびシステム依存を用意します。ソースモジュールを参照するシナリオのため、Vite の開発サーバーを localhost の固定ポートで起動します。
- `scripts/e2e.mjs` と存在する `scripts/e2e-*.mjs` を順に実行し、一つでも失敗したらジョブを失敗とします。自己起動型エディタのサーバーには別のポートを使います。`perf.mjs` は性能計測であり対象に含めません。
- スクリプトごとにログと `SLG_SHOTS` の画像を分け、失敗時も artifact として保存します。待機とジョブには上限を設けます。

## 要検証・見直し条件

20 分のジョブ上限と artifact の保存期間は仮置きです。シナリオが増えたときの実行時間・使用量や、ランナーの負荷、描画・操作タイミングによる不安定さを継続して確認します。失敗はログと画像で原因を調べ、実際の不具合と環境による揺れを区別します。検証を黙って無効化したり成功扱いにしたりしません。必要ならシナリオ分割・待機方法・時間上限を見直します。

CI 上の headless 実行は、実ディスプレイの操作感や性能基準の達成を示すものではありません。
