# 0004: ゲームのコードを責務ごとのモジュールに分ける

記録日：2026-11-12

状態：採用（プロトタイプのコード構成）。挙動は変えないリファクタリングです。

関連：[判断記録 0003](0003-map-prototype-canvas2d.md)、[概念設計](../architecture.md)、[プロトタイプの起動・操作](../../game/README.md)

対応する GitHub Issue はありません。

## 背景

幼少期マップのプロトタイプでは、`game/src/main.ts` に起動・入力・外見パネル・保存・更新ループ・HUD・計測用フックが集まり、`Game` クラスに移動・衝突、会話、外見、保存が同居していました。次に人生の状態やイベント（選択肢・結果）を加えるには、それぞれを置く場所と、UI の画面状態を1か所で判定する仕組みが必要です。

## 決定

- `main.ts` は部品の組み立てだけにし、更新ループ・保存先・計測用フックを `app/`、入力を `input/`、画面の表示と UI モードを `ui/` に分ける。
- UI のモード（探索／会話／外見パネル）は `ui/controller.ts` の `UiController.mode` で判定し、キー・タッチ・ボタンの振り分けをそこに集める。
- `Game`（`session/`）は組み合わせ役とし、移動・衝突・出入口は `map/`、会話の進行は `events/`、保存データの形式と検証は `state/` に分ける。
- 描画（`render/`）は `RenderView` という読み取り専用の形だけを参照し、`Game` に依存しない。
- 開始地点・出入口の戻り先は `world/landmarks.ts` と屋内の到着位置の定数で共有し、座標の直書きを重複させない。読み込むエリアは `AREA_FACTORIES` に登録する。年代ごとの文言（屋外の端での一言）は年代差分 `VariantDef.edgeMessage` に置く。
- 性能計測用の固定経路は本体から外し、`tests/fixtures/perf-routes.ts` に置く。

## 範囲外・未決定

- 保存形式（`slg-map-save-v1`）は変えていない。人生の状態（年齢・能力・資産・履歴など）や時間進行は仕様が未決定のため、`state/` に型やデータを追加していない。
- イベントの条件評価・選択肢・結果の仕組みは未実装。`events/` には既存の会話進行だけを移した。
- 型の細分化（`ObjectDef.kind` の文字列など）やコードの書式の整理は対象外。
