# 準都会の分割型マップ構造と制作・実装パイプラインの採用

状態：合意済み（描画ライブラリ・タイル寸法・画面解像度などの具体的数値・候補技術は未決定）

## 背景と課題

本作では、セキュリティに詳しくない一般のプレイヤーが、幼少期から高齢期までの人生シミュレーションを遊ぶ中で日常のリスクと対策を自然に学ぶ体験を目指しています。

マップと探索の設計にあたり、以下の点を明確にする必要がありました。

1. 町の舞台設定と、全年代を通じた生活感・帰属感の表現方法
2. 画面全体に収まる単一の一枚絵とするか、カメラ追従で歩ける分割型マップとするか
3. 画像生成によるビジュアル検討（参考画像）と、実際のゲームで動かすタイル・チャンク・当たり判定データの関係
4. マップ探索と、人生の時間進行・イベント発生条件評価との責務境界

## 検討した選択肢と判断

### 1. 舞台設定と年代変化の表現

- **採用した方針**：日本の準都会・地方中核都市の住宅／商業混在地域（低・中層ビル、戸建て住宅、マンション、駅前、商店街、学校、公園、川沿いが共存する町）を舞台とする。基本的な道路網と地理は全年代で一貫させ、店舗の開閉店・建物・装飾・NPC配置・居住地・アクセス条件を年代差分として切り替える。
- **採らなかった方針**：山間の小さな村に限定する案や、年代ごとに無関係なマップへ完全に作り替える案。
- **理由**：日常の生活要素（通学、買い物、就職、引っ越し、通院・介護、SNSや決済・Wi-Fi利用など）が自然に1つの生活圏でつながり、幼少期から老後まで同じ町を再訪して変化を感じることで、町への愛着と選択の長期的影響が伝わりやすくなるため。

### 2. マップの描画・分割方式

- **採用した方針**：単一の一枚絵を画面全体に収める方式は採らず、`エリア（街区・屋内） → チャンク／タイルレイヤー → 画像アセット` に分割し、主人公を追従するカメラで可視範囲を連続描画・必要に応じロードする。自宅や学校などは入口から内部マップへ遷移する。また、街区外縁は山や壁で不自然に塞がず、幹線道路・線路・遠景などで世界が外へ続く印象を保つ。
- **採らなかった方針**：町全体を1枚の固定画面画像として表示する方式、または単一の巨大PNGを常時メモリ展開する方式。
- **理由**：画面より広い町を歩いて生活圏を行き来する探索体験を実現しつつ、メモリ消費・初回ロード負荷を抑え、街区単位・年代単位での拡張や差し替えを容易にするため。

### 3. 画像制作から実装までのパイプライン

- **採用した方針**：「画像生成による雰囲気検討（参考画像） → 街区・施設・道路・出入口の平面設計（論理マップ） → タイル／アセット化と継ぎ目チェック → TypeScript による描画・操作の実装」の4段階で進める。参考画像（`assets/images/maps/previews/` 等）、編集可能な原本（`assets/sources/images/`）、ランタイム用書き出し画像（`assets/images/`）、構造化データ（JSON等）を分離する。
- **採らなかった方針**：生成した参考画像をそのまま引き伸ばしたり、無加工でシームレスな完成タイルデータとみなして直接配置したりする方式。
- **理由**：生成画像は視点・パレット・雰囲気の統一確認には有効だが、そのままでは道路接続の整合、正確なタイル寸法、当たり判定、ドア位置、チャンク境界の継ぎ目なし描画を保証できないため。

### 4. 時間進行・イベント評価との責務分離

- **採用した方針**：実装言語は TypeScript とし、マップ探索（描画・移動・衝突・遷移・インタラクト通知）と、人生の時間進行およびイベント条件評価を疎結合に分離する。フィールドの移動だけで勝手に季節や人生が進まないようにし、また危険な場所だけに警告表示を出したりセキュリティイベントだけを見た目で区別したりしない。
- **理由**：プレイヤーが安心して町を探索できるようにするとともに、イベントや年代差分の追加時にマップ描画コードへ条件分岐が混入するのを防ぎ、データ駆動での保守性・検証再現性を確保するため。
