# 0005: 資産の共通操作とv1保存への追加

記録日：2026-11-13

状態：採用（Issue #20 の基盤実装）。初期資金・アイテムの採用・数量上限・UI操作は暫定で、企画確定ではない。

関連：[Issue #20](https://github.com/kame447/gmo-security-life-game/issues/20)、[所持金・所持品](../features/inventory.md)、[モジュール構成](0004-game-module-structure.md)

## 背景

買い物や将来のイベントが、所持金・所持品を同じ規則で読み書きする必要がある。代金の減算後に数量上限で取得が失敗するなど、一部だけの反映を防ぎたい。既存の位置・外見セーブは引き継ぐ。

## 決定と理由

- 金額と個数の検証・一括更新を `state/assets.ts` の `PlayerAssets` に集約する。描画・マップ・店舗から独立させ、金額と品の両方を検証してから状態を置き換える。
- 円単位・安全な整数で扱い、小数誤差・負の残高・数量の不正値を防ぐ。個数上限とアイテム定義、仮の初期資金はデータへ分離する。価格は買い物担当のデータに置く。
- 参照・保存にはコピーを返す。呼出元が保存用オブジェクトや取得結果を編集しても実状態を壊さない。
- 保存キーと `v: 1` を維持し任意欄 `assets` を追加する。旧セーブは欠落欄だけ補う。対応する形式では不正位置だけを開始地点に戻し、外見や所持資産を巻き添えにして失わない。
- 存在する資産欄の不正金額は0円へ修復し、古い資産欄欠落のセーブにのみ仮の初期資金を補う。所持品の有効な行は残し、重複は集約して定義上限へ収める。
- 所持品画面は既存の `UiController` にモードを加え、探索中だけ開く。開閉時の押下解除とパネル内へのキー振り分けで、移動や会話との競合を防ぐ。

## 範囲外

消費効果・譲渡・売却・経済バランス・年齢進行の実装や確定、マップ・NPCの配置変更、クラウド同期は対象外。`apply` の個数減算と金額増加は将来の接続点であり、各生活行動の採用を意味しない。
