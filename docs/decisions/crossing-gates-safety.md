# 踏切の通行制限と歩行退避（#35、試作／要検証）

2026-11-15。[Issue #35](https://github.com/kame447/gmo-security-life-game/issues/35) の遮断機に関する判断。最終の運行間隔や演出値を確定するものではない。

## 判断と理由

- 遮断機は実マップの `CROSSING` から生成し、時刻を受け取る純粋な関数で状態を決める。定期列車と同じダイヤを読み、描画と移動に同じrAF時刻を渡す。描画のフレーム数や保存の有無によって閉じる時刻がずれないようにする。
- 静的な `canStand` のAPIを維持し、動的な入口の制限を `MapExplorer` に重ねる。防護柵は静的な地面・solidへ加えるが、一時的な閉鎖によっては変更しない。保存検証・ミニマップ・地理の到達性検証にも同じ保護帯が反映される。
- 内側からの北南への手動退出を歩き・走りで受け付ける。入力を全面的に止める旧方式は、閉鎖中の本人の退出操作を妨げるため改める。静止や退出に間に合わない逆入力では安全な側へ歩行退避し、入力の有無にかかわらず列車との重なりを防ぐ。走りを途中でやめても歩いて逃げ切れる余裕を残し、通常のフレームでは瞬間的な補正を使わない。
- 退避は `app/loop.ts` から描画前に進める。全体地図では通常のゲーム更新が止まるが、踏切の上でも地図を開けるため、この状態でも退避が必要になる。探索器は弱参照で登録し、ゲームの保存やUIの契約には状態を追加しない。
- 再読込やタブの長い停止で歩く時間が足りない場合だけ、最初の列車描画前に安全な待機位置へ戻す。通常の閉鎖では歩く連続性を保ち、復帰時は列車との重なりを防ぐことを優先する。
- 予告2秒、上下動各0.7秒、退避の余裕0.35秒、1周期の連続開放下限8秒を仮値として1設定にまとめる。予告は保護区間全長88pxの歩行時間と余裕の合計より長く保つ。12秒周期では渡れる時間が短かったため、速さ・長さ・経路を維持して周期だけを仮30秒に延ばす。単線区間の対向非競合と、全踏切の8秒以上の開放を回帰テストで固定する。
- 支柱とバーを線路際へ寄せ、車体と人物の絵が触れない待機位置は停止線で示す。従来は待機位置と支柱が同じ座標だったため、遮断機が線路から離れて見えた。新しい座標を同じ `Crossing` にまとめ、横断口の幅と進入・退出の判定を共有する。
- 線路の両脇を2タイルの静的保護帯と外周の柵で囲い、開口以外からの進入と横断口の横漏れを防ぐ。単なる柵の上描きでは経路探索や保存検証と衝突がずれるため、`RAIL_GUARD` の地面データから描画とsolidを生成する。川・堤・線路自体は保つ。

## 影響と検証

構内の乗車演出、自動歩行の経路、`getStationFlow`・`stationScene`、保存形式は変えない。動きを減らす設定はバーの補間と警報灯の点滅を抑え、通行制限と退避の安全性を維持する。

単体試験は全踏切の周期走査、通行、手動退出、退避、保存復帰、時刻飛び、減動、連続防護柵を扱う。再修正後はVitest347件・CLI13件・tsc・buildが合格。PC・スマホ縦横のheadless E2Eは、手動退出と柵の検査を加えた170項目が合格し、安全検査3472フレームで列車との重なりなし（Macの実行環境、2026-11-15）。撮影・録画のスクリプトと仮値の詳細は[マップと探索](../features/map.md)を参照。実画面の利用者確認は別途必要とする。
