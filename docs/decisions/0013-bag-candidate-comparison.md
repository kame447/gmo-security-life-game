# 0013: バッグの候補比較と一時セッション

- 状態: 利用者レビュー前の候補
- 関連: Issue #20、#21、#22

旧PR #28の画面は採用されていないため、資産・保存の内部処理だけを再利用し、新しい1層グリッドとクイック枠付きグリッドを比較する。通常／重要を区分の基本とし、クイック枠の採否は決めない。服のUIは所持表示に留め、能力や装備欄を設けない。

候補ごとにDOM・CSS・アイコンを別モジュールへ置き、共通モーダル登録口で1つだけを生成する。共通コントローラーと実マップ・NPC・外見・描画は変更しない。既存のみため編集の未確定外見を保存しない処理も維持する。

比較条件を揃えるため、同じアイテム定義・資産API・暫定fixtureを使用する。レビューURLの `review=1` は読込を省略し、全保存経路の共通入口で書込を止める。通常セーブを比較操作で上書きしない。候補のURL切替はレビュー専用で、セーブ形式の設定値にはしない。

通常URLも提供するため、単独候補で使わない既知の保存欄も保持する。共通保存は資産を第4引数、スマホを第5引数にし、スマホのcodecを画面・アプリ定義から分離する。バッグやショップのセッションはcodec済みDTOだけを保持し、スマホ側は同じcodecへ動作中のモデルの保存値を渡す。位置修復で有効な別欄を消さず、読込・モデル・保存で同じ容量設定を用いる。

採用の判断はスクリーンショットと実ゲームの操作を利用者が確認して行う。ビルド・テストの成功は視覚品質の承認を意味しない。採用前にPRを作成せず、旧PRを再オープンしない。

## 2026-11-14: 着せ替えのデータ契約

服の所持は既存の資産に集約し、外見の変更は独立した純粋関数とする。`data/clothing.ts` にitem IDから `outfit`・`outfitColor` への暫定の対応を置き、既存の外見・描画ファイルは変更しない。

`state/wardrobe.ts` は現在の所持を確認し、成功時に服だけを変えた外見と、服だけの取消用データを返す。取消は現在の髪・体形を巻き戻さず、資産も更新しない。取得や会計を取消と結びつけず、将来の店・イベントは既存の原子的な資産APIを使える。

保存は既存の外見の形と色を使い、所持服がない旧外見を強制的に変更しない。旧保存の移行、着用後に服を失った場合、編集の入口・確定・保存、入手条件・場所・物語は未決定。今回の契約はUIや既存のみため画面へ接続せず、画面の採否も変更しない。
