# 0013: バッグとホットバーの共通インベントリ

- 状態: 方向性は採用、画面は利用者の確認前
- 関連: Issue #20、#21、#22

2026-11-14の利用者レビューで、バッグ内のグリッドと探索HUDのホットバーを同じ所持品として扱う方向を採用した。旧候補のitem IDを別のクイック枠へ登録する方式は最終操作にしない。旧PR #28は未マージのまま閉じ、実画面で明示的な承認を得るまで新しいPRは作らない。

## 数量と置き場所

数量は既存の `assets.items`、一意の置き場所と選択枠は任意の `assets.layout` に持つ。各品はバッグかホットバーの一か所だけに現れる。配置に数量を複製せず、既存の購入APIと原子的な数量更新を保つ。

同じ画面に二つの置き場所を並べ、空きへの移動と占有枠との交換を共通APIで行う。UIの選択待ちは一時状態で、移動を決めるまで所持品を変えない。元の品が消えた場合は別の品を動かさず取消す。HUDは別の登録情報を持たず、同じ資産から描画する。

04:47の利用者レビューに従い、操作の説明文・下段の見出し・枠番号を表示せず、品数は残す。最初のクリックはUI内の選択だけとし、配置と保存を変えない。移動先の明示的な確定か、有効なドラッグ＆ドロップでだけ配置を変更する。キーボードもEnter／Spaceの2段階とし、数字などの焦点移動を確定として扱わない。スクロール・無効ドロップ・取消では変更しない。

通常／重要は品の属性であり、置き場所の分類ではない。試作の5列・バッグ3段・ホットバー5枠は設定に分離する。行は増やせるため新しい所持容量制限ではない。重要品の配置制約、分割操作、最終の枠数や配色は決めない。

## 保存とレビュー

既存のv1資産と旧セーブを維持する。配置がない保存はバッグへ順に置き、破損した配置だけを補修する。有効なスマホの所持・残量・会話は、独立した最新の共有codecで保持する。位置を直すために他の欄を消さない。

`review=1` は通常セーブの読込と全保存経路の書込を止める。一時的な共通サンプルで操作・撮影・録画を比較し、初期所持・入手時期や物語を決めない。純モデルと実Gameの保存、ブラウザでのドラッグ・タップ・キーボードと3サイズを分けて検証する。テスト成功は画面品質の承認とは別に扱う。

着せ替えの純粋なデータ契約は `feat/clothing-contract` で独立して検証済み。このブランチでは画面へ接続せず、外見・描画・マップ・NPCは変更しない。
