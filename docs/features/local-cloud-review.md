# クラウド保存・アカウントのローカル確認版

Issue #20 の保存・認証の操作を、外部サービスへ接続せず確認するための画面。確認用アカウント A / B でログイン・ログアウトし、現在の進行を保存、内容を確認して読み込み、複数の端末から保存したときの競合を試せる。本番の Cognito 認証と AWS の保存先には接続していない。この状態は画面にも常に表示する。メールアドレス・パスワード・認証トークンは入力も保存も不要。

## 接続方法

`LocalCloudReviewPanel` の `root` を既存のセーブ画面へ追加する。開いたときに `refresh()` を呼ぶと前回の未確定の確認を閉じる。`getCurrentSave()` は明示的な保存・競合確認の操作でのみ呼び、起動やログインで現在の進行を勝手に保存しない。

```ts
const cloud = new LocalCloudReviewPanel({
  getCurrentSave: () => completeSave(),
  onRestore: async save => safelyReplaceAndReload(save),
});
cloudHost.append(cloud.root);
cloud.refresh();
```

`onRestore` は `Promise<boolean>` を返す。ホストが現在の保存済み記録の退避、world・phone・story の形式確認、既存の保護データの確認、ローカル保存の成功を扱う。未保存の進行まで退避するとは表示しない。`true` のときだけ確認用の読込を受理し、`false` または例外では読込候補を保持する。確認用 gateway 自体は `slg-map-save-v1` を読み書きせず、ゲームの再開やリロードもしない。

## 保存先と既存コードの利用

専用キー `slg-cloud-review-v1:account-a:main` と `slg-cloud-review-v1:account-b:main` に、確認用の主体、SaveEnvelope、最後の書込キーを記録する。ログイン状態はメモリだけに持ち、リロードするとログアウトになる。ログアウトしても確認用の保存は消さない。アカウントを変えるとそのアカウントの保存のみを表示する。

既存の保存API候補から `save-api/contract.ts` と `save-api/server.ts` を無改変で取り込み、形式検証、320 KiB の暫定容量、保存番号、冪等キー、純粋な `readSave` / `writeSave` を再利用した。保存形式や比較更新を別の規則に作り直していない。認証済み主体を受け取る本番の境界に、確認用 A/B を本物のアカウントとしてつなぐことはない。ここでの主体は純粋な処理の確認用入力である。

既存の CloudSaveBridge / CloudSaveCoordinator の HTTP、認証セッション、成功済みローカル保存の証明、未送信ジャーナルは今回は本編に接続しない。今回のUIが扱うのはブラウザー内の確認用データであり、実際のクラウド送信を有効にするための同意や認証の代替ではない。本番に接続する際は、成功したローカル保存の完全DTOだけを送る Coordinator の規則と認証担当の契約を使う。

## 競合・中断・失敗

確認用 gateway は最後に確認した保存番号を保持し、保存前に現在の番号と比較する。別の確認用端末またはタブが更新済みなら、既存 API と同じ 409 / `REVISION_CONFLICT` になる。現在のゲームと保存先を自動的に混ぜたり、強制上書きしたりしない。保存内容のプレビューだけでは、この端末の期待する番号を更新しない。ホストが復元を受理したときだけ更新する。

「競合を試す」は、別の確認用端末に相当する操作で保存番号を進め、元の番号のままこの端末から保存する。エラー表示を固定で偽装するのではなく、実際の比較更新処理が競合を返す。確認用データしか変更しない。

ブラウザーが Web Locks を提供する場合は、同じ確認用アカウントの読み書きを同じロックで直列化する。未対応ブラウザーでは一つの画面内の同期処理として動作するが、複数タブ同時書込の原子的な保証はない。本番の DynamoDB 等の排他制御の検証を意味しない。

ログアウトとアカウント切替のたびに世代番号を進め、待機中の古い保存や読込結果を別のアカウントへ適用しない。同じアカウントへログインし直した場合にも古い読込候補を使えない。壊れた保存、未来の形式、容量超過、保存領域エラーでは元の文字列を保持し、本文や履歴を削って保存しない。現在の通常セーブはホストの既存処理が管理する。

## 確認

`tests/local-cloud-review.test.ts` は未ログイン拒否、A/B分離、再読込、未知欄の保持、古い保存番号の拒否、明示的な復元受理、ログアウト中の遅延処理、壊れた保存、容量不足、上限超過を検査する。UIの `data-cloud-action` 属性は実ブラウザーでの操作確認に使える。ローカル版の確認を、本番認証・本番クラウドの接続完了として扱わない。

`SLG_URL=http://127.0.0.1:5494 SLG_SHOTS=docs/review/local-cloud node scripts/e2e-local-cloud-review.mjs` は実際のセーブ画面を PC・390px の独立ブラウザーcontextで開き、アカウント分離、保存確認、読み込みの中止、容量不足時の復元拒否、競合、復元後の再読み込みを確認する。通常保存キーに置いたsentinelが変わらないことと、外部HTTPリクエストが発生しないことも検査する。`localReview=save` 専用のゲーム保存を使う。画面のスクリーンショットは指定先に出力する。
