# 保存と復元のローカル確認版

2026-11-28の利用者指示に基づく承認前のローカル実装。関連課題は #20 と #50。既存の通常セーブキーと v1 形式を維持し、保存した日時だけ省略可能な欄として付ける。既存の保存基盤候補も参照したが、無制限の backup や previous/protected の二重管理は導入しない。

ゲームの「保存」または O キーで保存画面を開く。「保存する」はその場で保存し、「保存してタイトルへ」は書込みが成功してからタイトルへ移る。タイトルの「つづきから」の下に前回の保存日時を示す。既存の日時がない保存も読み込める。

現行保存とは別の recovery-v1 キーに最大3件の復元ポイントを持つ。再開後の最初の変更、明示保存による上書き、新規開始、復元の直前に保護し、3秒ごとの自動保存で世代を増やさない。同じ内容は日時だけ変わっても重複させず、4件目は最も古い世代から置き換える。新規開始も元の内容の退避・読み返しが成功してから現行保存を消す。保存や退避に失敗した場合はタイトルへの移動や新規開始を止める。

復元の対象は保存済みの記録であり、最後の保存後の操作まで遡って採取しない。復元前の保存済み記録を保護したうえで選択した記録を書き戻し、古いゲームの全保存入口を停止して読み込み直す。保存クラス自身も、復元後の古い状態からの保存を拒否する。別タブが変更した記録を検出した場合は上書きを止める。localStorageには複数タブを横断する比較・交換操作はないため、Cognito接続時のrevision管理と同一の保証ではない。

読み取れない形式、未知のストーリー/スマホ世代は勝手に新規ゲームへ置き換えない。過去の復元ポイントが読める場合はタイトルから戻せる。既存の別実装のバックアップキーや通常プレイとは別ポートのセーブには触れない。

localReviewパラメーターを持つ確認用場面は専用のキーを使い、通常のセーブから分離する。クラウド認証の確認用UIは別仕様書のローカル体験であり、本番Cognito・DynamoDBとの通信は未接続。実接続には環境と認証仕様・APIの合意が必要。
