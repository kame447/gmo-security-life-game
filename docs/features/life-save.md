# 人生イベントの保存用アダプタ

対象は [Issue #20](https://github.com/kame447/gmo-security-life-game/issues/20) と、[PR #51](https://github.com/kame447/gmo-security-life-game/pull/51) で入った `LifeStateData`。[イベント基盤](life-events.md) の保存形式と、[ローカルセーブ](local-save.md) への接続候補を扱う。

独立アダプタは `feat/life-state-save` d5b555f の3ファイル。接続候補 `feat/life-local-save` は、バッグ・買い物・ローカルセーブの統合プレビュー `preview/local-save-combined` 7632065 を基点に、その3ファイルを取り込んだもの。この候補では Game と Director の状態を共有し、確定済みの数値・目印・履歴を保存・復元する。既存の5296プレビュー、main、PR #54/#55は変更しない。PR作成と統合、保護時の扱いの正式採用は利用者レビュー後とする。保存API・AWSには接続しない。

## 境界と形式

実装は `game/src/events/life-save.ts`。外側のセーブの版・variantを検証した後、任意の `life` 欄だけを `restoreLifeSave(rawLife)` に渡す。最上位のセーブの版と `life.v` は別の契約である。

```json
{
  "v": 1,
  "stats": { "friendship": 2.5 },
  "flags": { "asked": true, "future.flag": false },
  "history": [
    { "eventId": "sample.tablet-ad", "choiceId": "ask-parent" },
    { "eventId": "conversation", "choiceId": null }
  ]
}
```

`LifeSaveData` は既存の `LifeStateData` を拡張した plain JSON。数値・目印のキー、イベントID・選択IDは現時点の定義一覧で削らない。負数・小数の有限数、false、nullの選択、履歴の順序・重複を保持する。数値の意味・範囲や採用するイベントは決定しない。

v1の最上位と履歴要素の未知メンバーも、入れ子のJSONごと保持する。未知メンバーの中にある版番号は解釈しない。例として未知の `future: { v: 7 }` は保持するが、`life.v: 7` はこの版の状態として使わない。`stats` の値は数値、`flags` の値は真偽値という契約があるため、そこで型が異なる値を未知の追加仕様と決めつけない。

## 復元と上書きの可否

返り値の `state` を `LifeEventDirector` に渡す。`status` と `issues` は読込結果を示し、`serialize({ maxBytes? })` が保存用の独立したJSONを作る。

| status | state | serialize |
| --- | --- | --- |
| `missing` | `life` がない旧セーブの空状態 | v1を新規作成できる |
| `ready` | 有効なv1を復元 | 未知欄を保持して保存できる |
| `recovered` | v1の読める欄・要素を局所回復 | `protected-life` で拒否 |
| `protected` | 未対応版は空状態。JSON以外の値を含むv1は安全に読める部分だけ復元 | `protected-life` で拒否 |

引数の省略・undefinedを、旧セーブに `life` がない場合の表現とする。外側に明示的なundefinedの欄がある入力を許すかは、外側のJSON検証の責務である。nullや版番号欠損を「新規」として上書きしない。

局所回復では、不正なstat・flagは実行時状態から除き、ほかの値を保つ。履歴の `eventId` が文字列で `choiceId` だけが不正・欠損なら、実行時には `choiceId: null` として経験済みを保つ。これにより既存Directorの一度きり判定が働き、同じ効果を重ねない。特定の選択をしたという条件は捏造しない。イベントIDまで壊れた要素から、どのイベントの経験かを推定することはしない。

回復できることは元データの削除許可ではない。アダプタは `recovered` と `protected` からの保存を拒否する。接続候補は元のlife JSONを運搬するだけで、回復した人生の状態を元データに上書きしない。回復状態そのものの採用には、元のセーブを保護し、別のアダプタへ明示的に切り替える設計が必要。このモジュールには上書き許可フラグや自動退避処理を置かない。

復元時にはeffectを再適用しない。選択待ちのUI状態も保存しない。確定済み履歴は一度きりの再発を抑え、未選択・中断は経験にせず、`once: false` は引き続き反復できる。`record()` による追記は保存できるが、復元済み履歴の削除・並べ替え・選択の書換えは `invalid-data` で拒否する。未知の履歴メタデータを別の経験へ付け替えないためである。新しい人生の開始は、以前のアダプタを流用せず、別の状態として接続側で扱う。

## JSONと容量

保存前に、新しい状態にも型・構造の検証を行う。加算によるInfinityなども拒否し、JSONのnullへ変換して通さない。Map・Date・関数・undefined・BigInt・Symbol・循環・疎配列・アクセサ・非列挙メンバー・深さ64超は保存対象にしない。getterやtoJSONは検証のために実行しない。検証済み入力と出力はコピーし、呼出側が後から変更しても、保持している未知欄に影響させない。

`LifeSaveError.reason` は `protected-life`、`invalid-data`、`too-large`。診断はJSON pointerと種別だけで、値の内容は含めない。

`maxBytes` は**life欄のJSON単体**のUTF-8バイト数への任意の上限で、ちょうど上限は受理し、1バイト超過は拒否する。省略時のバイト上限や履歴件数の上限は設けない。超過時も履歴や未知欄を切り詰めない。最上位セーブ全体とAPI封筒の容量は、それぞれの保存層で改めて検証する。API候補の容量をこのモジュールに複製しない。

## 本編への接続候補

`Game` は、外側のセーブを検証した後の `life` を一度だけ復元し、`game.life` にアダプタを持つ。`main.ts` の Director には `game.life.state` を渡す。数値・目印・履歴を二つの状態に分けない。`Game.serialize()` 単独にもlifeを含めるため、購入・バッグ・スマホと同じ保存経路を使える。

`missing` は空のv1を保存し、`ready` は未知欄を保持した最新の状態を保存する。選択中のUIは保存せず、確定済み履歴だけを引き継ぐ。「つづきから」は保存時点の状態でGameとDirectorを作り直し、旧ページのpagehideは書き込まない。「スタート地点へ」は人生の状態を保持する。確認した「はじめから」では、既存の `.previous` 退避が成功してから空のlifeを保存し、再読込する。

**保護時の仮の選択**：`recovered` / `protected` では、Gameは元の検証済みlife JSONをそのまま出力する。保存層も書込直前のディスクのlifeを確認し、保護対象ならその値を優先して保持する。位置・外見・所持金・バッグ・スマホの書込は続けるが、新しい人生イベントの進行は元のlifeへ混ぜない。全体を保存拒否すると他の進捗も保存できなくなるため、この候補では欄ごとの保護を選んだ。回復状態の正式採用方法は未決定のまま。

`writeSave` のtrueはsetItemの成功を示す。`saveStatus().lifeProtected` は、その書込でも新しい人生イベントの進行を保存できなかったことを示す。`LocalSaveSession` はこの場合 `protected-life` を返し、既存のエラー通知を使う。「セーブしました」は表示しない。新しいパネル・文言・見た目は追加しない。Gameの `life.status` / `issues` でも回復・保護状態を取得できる。

通常の自動保存、pagehide、手動保存では、スナップショットを作る関数をLocalSaveSessionへ渡す。保存の保留・切替判定の後にその関数を呼ぶ。実行時の非有限数等でlifeの生成が失敗した場合は、全体を書き込まず `invalid-data` / `too-large` 等の失敗通知へ伝える。lifeだけを省いて成功扱いにしない。容量不足でも旧チェックポイントは変えず、再試行は現在のGameから行う。

外側のcodecは復元前のlifeを不透明なJSONとして保つ。lifeを含むスナップショットではその欄を既知の位置に並べ、通常ページの離脱で同じ内容のJSONのキー順だけが変わることを防ぐ。lifeを省略する旧呼出元では、以前と同じく既存欄を保持する。未来版のphone等による外側全体の拒否・退避契約は変更しない。

別タブの有効なv1同士は従来の後勝ちを維持し、履歴を自動マージしない。保護状態のGameがある間に別タブがlifeを回復・変更した場合は、より新しいディスクのlifeを保持し、このGame側は再読込するまで部分保存として通知する。localStorageの確認と書込の間を原子的に排他する保証は追加しない。

## 検証と未決定事項

`game/tests/life-save.test.ts` は独立アダプタの30件。旧v1、局所回復、未来版、未知欄、コピーの独立、サンプルの全3選択・後続分岐、一度きり／反復／未選択、異常値、UTF-8容量と6,000件の履歴を扱う。`life-local-save.test.ts` は実際のstorage → Game → Director → storageと別セッションの復元、保護時の部分保存、別タブの未来版、once／反復、容量・生成失敗、確認した新規開始と離脱時の保留を扱う。`scripts/e2e-life-save.mjs` は使い捨てブラウザで実UIの選択・保存・復帰と失敗通知を確認する。確認先は専用の5298とし、既存5296の状態やユーザーのブラウザプロファイルに触れない。

未決定は、rawを保持して他欄を保存する仮の選択の正式採用、回復状態を採用する操作・表示、保護中に増えたlifeの扱い、履歴の長期保持方針、APIと最上位セーブの採用容量。保護中の新しいlifeはメモリ内だけにあり、再読込で失われるため、成功通知にはしない。保存上限・履歴圧縮・新しいイベントや年代の採用は決めない。設計理由はこの文書へ記録し、採番を伴う判断記録は後段の合意時に行う。
