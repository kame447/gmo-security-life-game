# 所持金とバッグ

Issue #20 の資産・保存基盤と、ホットバー一体型インベントリを扱う。2026-11-14に方向性は採用されたが、画面は利用者の実操作レビュー前。旧PR #28は未マージでクローズしたままとし、新しいPRは実画面の明示的な承認後に作る。

## 資産と置き場所

所持金は円単位の非負の安全な整数。アイテムのID・名称・説明・通常／重要の属性・個数上限は `game/src/data/items.ts` に置く。`game.assets` の `changeMoney`、`addItem`、`removeItem`、`apply` を使い、複数の金額・数量変更は一括で成功／失敗する。

数量の正本は `assets.items` に一つだけ持つ。`assets.layout` は各item IDの置き場所をバッグ内かホットバーのどちらか一か所へ割り当てる。表示用の `assets.inventory()` は同じ数量から両方を作り、バッグから移した品をバッグにも残さない。旧候補のショートカット登録とは異なり、置き場所そのものが変わる。

- `assets.moveStack(from, to)` は `{ section: 'bag' | 'hotbar', index }` の間で一つの品の全個数を移動する。移動先が埋まっていれば入れ替える。財布と総個数は変わらない。
- `assets.selectHotbar(index)` は探索HUDとバッグ画面で共通の選択枠を変える。`assets.inventoryLayout` は保存用の配置、`assets.inventory()` は数量を含む表示用のコピーを返す。
- 取引で数量が増減しても、その品の置き場所を保つ。0個になった品だけ枠を空け、新規取得はバッグの空きへ置く。移動を始めたあとに品がなくなった場合、その移動は取り消す。

`data/inventory-config.ts` の5列・バッグ3段・ホットバー5枠は暫定。必要ならバッグの行を増やし、新しい所持容量制限にはしない。1個ずつの分割、通常27＋ホットバー9などの最終枠数、重要品をホットバーに置けるかという正式な方針は未決定。今回の試作では属性で置き場所を制限せず、詳細に通常／重要を表示する。

## 画面と操作

同じ画面にバッグのグリッドと、その下の枠を置く。選択した品だけ名称・属性・個数・説明を表示し、所持金は上部へまとめる。操作の説明文、下段の見出し、枠内の番号は表示しない。品数は表示する。登録・解除、未実装の使用・廃棄ボタンは置かない。

クリック／タップの1回目は移動元の選択だけで、資産・配置・保存を変えない。移動先をクリックして確定するか、有効な移動先へドラッグ＆ドロップしたときだけ移動・交換する。同じ枠の高速ダブルクリックは不要。無効なドロップ・取消・スクロールやドラッグ終了後の余分なクリックでは移動しない。

バッグ内では矢印／WASD／Tab／数字キーは焦点と選択だけを動かす。Enter／Spaceの1回目で移動元を選び、移動先で2回目を押して確定する。数字やZだけでは移動しない。Esc・同じ移動元の枠・取消ボタンは移動待ちを取り消す。もう一度EscまたはI、閉じるボタンでバッグを閉じる。Iのキーリピートでは開閉を繰り返さない。焦点のある閉じる・取消ボタンへのEnter／Spaceは、そのボタンを実行する。

探索中のホットバーは同じ配置・個数・選択を表示し、数字キーまたはクリック／タップで選べる。会話・外見・他モーダルの間は隠し、探索入力と競合させない。枠の選択に使用効果はない。既存のみため画面や着せ替えの操作は変更しない。

## 保存と旧データ

v1の保存形式とキーを維持し、資産欄へ任意の `layout: { v: 1, bag, hotbar, selectedHotbar }` を加える。配列は品IDかnullで、数量を複製しない。配置と選択を変えたら既存の保存コールバックを呼ぶ。

旧保存に配置がなければ、既存の順で品をバッグへ並べ、ホットバーは空にする。UIを作るときにこの配置を実体化する。破損した配置では未知IDと重複を除き、未配置の正当な所持品をバッグの空きへ補う。有効なホットバーの位置を優先し、財布・数量は配置修復のために変えない。

位置・外見・資産・スマホは独立して復旧する。通常保存では `phone.chat` も共有codecで保持し、位置だけが不正でもスマホを初期化しない。バッグはスマホ画面や消費時計を作らず、純粋なDTOを保持する。codecは `phone/save.ts`・`phone/chat/codec.ts` と通信容量側のものを使う。

`createSave(world, player, appearance, assets?, phone?, budgetConfig?)` の第4引数は資産、第5はスマホ。独自の通信設定は `loadSave`、Game、保存codecに同じものを渡す。今回の変更でGame・保存ストア・外見のファイルは書き換えない。

## 比較用セッションと検証

`?review=1` は既存セーブを読まず、起動・定期保存・ページ離脱・リセット・みため確定・配置変更からも保存を書かない一時セッション。`data/bag-review-fixture.ts` の所持金2,480円と10品を使う。通常の初期資金1,000円や初期所持品、価格・効果・入手条件の確定にはしない。

`?review=1` を含め、このブランチの既定のバッグは新しいHotbarPanel。以前の `?bag=grid` / `?bag=hotbar` 比較は凍結した候補ブランチの記録として扱う。

単体テストは移動・交換での個数保存、取引の原子性、配置修復、旧保存、配置・選択とchatの実保存復帰を確かめる。実ブラウザ用の `scripts/e2e-bag-inventory.mjs` はドラッグ・タップ・キーボード、HUD同期、通常保存、レビュー分離、3サイズを検証する。旧 `e2e-bag-hotbar.mjs` は同じ検査への入口とする。

`SLG_URL` で対象サーバーを指定する。`shots-bag-inventory.mjs` は `SLG_SHOTS` に3サイズ各8状態を、`video-bag-inventory.mjs` は `SLG_VIDEOS` に3サイズの操作を保存する。撮影・録画は常に一時セッションを使う。今回の画面・配色・枠数の承認には、親による実行と利用者の実画面確認が必要。

服の着せ替えの非UI契約は別ブランチ `feat/clothing-contract` の `b0f51ef` で管理する。この画面では服も所持品として移動するだけで、服を選んでも外見は変更しない。
