# 所持金とバッグ

Issue #20 の資産・保存基盤と、利用者レビュー前のバッグ候補を扱う。旧 PR #28 は未マージでクローズ済み。候補の採用と新しい PR の作成は、比較画面と実ゲームの操作を利用者が確認した後に行う。

比較方法と保存分離の理由は [判断記録0013](../decisions/0013-bag-candidate-comparison.md) に記載する。

## 資産と保存

- 所持金は円単位の非負の安全な整数。アイテム ID、名称、説明、区分、個数上限は `game/src/data/items.ts` に置く。
- `game.assets` の `changeMoney`、`addItem`、`removeItem`、`apply` を共通 API とする。複数の金額・数量変更は `apply` で一括検証し、失敗時は全項目を変更しない。
- 保存は既存の v1 形式とキーを維持し、位置・外見に `assets` を加える。旧 v1 の資産欄がない場合は仮の初期値へ戻す。破損した金額・数量と位置は独立して修復し、有効な外見と資産を残す。
- 通常保存はスマホの `phone` 欄も共通codecで保持する。バッグ・ショップだけの候補では、スマホ画面や消費時計を作らず、所持状態・通信残量・有効な任意の保存時刻情報を往復する。位置だけが不正でも `phone` を初期化しない。
- 初期資金 1,000 円は暫定。通常起動時のバッグは空で、レビュー用サンプルを初期所持品にはしない。

## レビュー候補（未採用）

全年代に使える「通常／重要」の区分を基本とし、候補 A はグリッドとクイック枠、候補 B は 1 層のグリッドで比較する。クイック枠の本採用、枠数、配色、並び順は未決定。説明は選択品に必要な内容だけを表示する。

バッグ候補のUIは、服を通常アイテムとして所持表示するだけに留める。能力補正や装備欄は設けない。着せ替えのデータ契約は後段に記載し、画面の入口と既存のみため機能の責務は別途検討する。

## 共通の比較データ

`game/src/data/bag-review-fixture.ts` の `BAG_REVIEW_ASSETS` と `applyBagReviewFixture(assets)` を両候補で使う。所持金 2,480 円、ノート 2、えんぴつ 12、水 3、おかし 2、ハンカチ 1、パン 2、シャツ 1、かさ 1、鍵 1、カード 1 を一時サンプルとする。内容・区分・上限に物語や効果の採用を含めない。

レビュー専用 URL は `?bag=grid&review=1` と `?bag=hotbar&review=1`。接続時は既存セーブを読まず共通サンプルで起動し、定期保存、画面離脱、リセット、みための決定などからの保存も行わない。一時セッションの変更は通常セーブへ混ぜない。`review=1` のない通常起動では既存の読込・保存を維持する。

商品価格、使用・譲渡・鍵の効果、カードの用途、服の着替え操作はこの比較データでは定義しない。

## 候補の操作と比較

| 候補 | 構成 | 操作 | 探索中 |
| --- | --- | --- | --- |
| B: `?bag=grid&review=1` | 通常／重要の切替、4列の1層グリッド、選択品の詳細 | 枠をクリック／タップ。矢印・WASDで選択、タブ上の左右または角括弧キーで区分変更 | 追加のバーを表示しない |
| A: `?bag=hotbar&review=1` | グリッドと5個のクイック枠 | 品を選んで枠を押す、または1〜5で割当 | 枠のタップ／1〜5で選択。使用効果はない |

どちらも「もちもの」ボタンまたは I で開き、×・Esc・Iで閉じる。Tabの焦点は画面内に留め、フォーカスした閉じるボタンへのEnter／Spaceはそのボタンだけを実行する。会話や他パネルの表示中は開かず、バッグ内の移動入力を探索に流さない。

Aのクイック枠は同じ資産のitem IDを参照し、個数を複製しない。所持数0になった参照を解除する。割当は一時状態で保存しない。Bの空欄は一覧の見た目であり、所持容量12枠というゲーム上の制限ではない。

起動時に候補指定を省略した場合は比較用のBを表示する。この既定値に採用決定の意味はない。候補の切替はURLでページを開き直して行う。

撮影は `game/scripts/shots-inventory.mjs` で行う。両候補を1280×800と390×844、同じ所持品・位置・外見で起動し、通常一覧、えんぴつ、服、重要一覧、重要品だけ空、全所持品が空を揃える。Aは割当後と探索中のバーも追加する。書込先は `SLG_SHOTS` のみ。ブラウザ操作は `scripts/e2e-inventory.mjs` と `scripts/e2e-bag-hotbar.mjs`、既存探索は `scripts/e2e.mjs` で確認する。

## 着せ替えのデータ契約（UI未接続）

`game/src/data/clothing.ts` は服のitem IDを、既存の `outfit`・`outfitColor` だけに対応させる。暫定の1件は `shirt` → `shirt` / `blue`。既存の外見で白を指定できないため、アイテム説明から色の断定を外した。色・形の追加や色違いの販売方法は決めない。

`game/src/state/wardrobe.ts` は、正規化済みの外見と現在の資産スナップショットを受け取る純粋関数を提供する。

- `canWearClothing(itemId, assets.snapshot())`: 定義のある服を1個以上所持しているかを判定する。
- `wearClothing(appearance, itemId, assets.snapshot())`: 未所持・服以外は失敗を返す。成功時は服の形と色だけを変えた新しい外見と、取消用の `previous` を返す。髪・体形と入力データは変更しない。
- `restoreClothing(currentAppearance, previous)`: 服だけを元へ戻した新しい外見を返す。その後に変えた髪・体形は保ち、取消時の所持条件は課さない。

服の取得・購入は既存の `assets.addItem` / `assets.apply` で扱い、着せ替えは財布も個数も更新しない。将来の確定操作では、その時点の資産で着られるかを再判定する。着せ替えの取消は購入の返金や服の消費を兼ねない。

外見の保存は既存の `appearance` の値を使い、新しい保存欄は追加しない。服を所持していない旧保存の外見も変更しない。適用後の服を手放した場合の扱い、未所持の試着、入手・購入条件、着替える場所、編集セッションの確定と保存は未決定。今回は既存のみため画面やバッグへの接続を行わず、シャツを選んでも外見は変わらない。

## 共通保存の接続

`createSave(world, player, appearance, assets?, phone?, budgetConfig?)` の第4引数を資産、第5をスマホに揃える。`parseSave(raw, world, initialPhoneOwned?, budgetConfig?)` は対応するv/variantを確認した後、位置・外見・資産・スマホを別々に復旧する。未対応のv/variantは引き続き拒否する。

スマホのDTOとcodecは `game/src/phone/save.ts`、通信残量のcodecと設定は `phone/budget.ts`・`budget-config.ts` を共有する。codecは時計を読まず、消費しない。スマホ側が独自設定を使う場合は `loadSave(world, { initialPhoneOwned, phoneDataConfig })`、Game、PhoneModel、保存直前の正規化へ同じ設定を渡す。通信容量の数値や時間方針はスマホ機能側の暫定設定であり、バッグは変更しない。
