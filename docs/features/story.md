# ストーリーの流れ（序章とステージ進行）

状態：利用者の指示（2026-11-18）による提案。チームへの共有・合意待ち。試作を `feat/story-flow`（マージ済み）と `feat/story-full-life` で実装中（[実装状況](#実装状況試作)）。年代の進め方は [判断記録 0015](../decisions/0015-story-time-limited-stages.md) で一度制限時間制にしたが、[判断記録 0016](../decisions/0016-story-milestone-unlock.md)（2026-11-27）で制限時間をやめ、必須イベントの解放と自分で選ぶ節目に変えた。

オープニングの後、中学生の主人公が家の2階で目覚め、母親からスマホを渡され、お使いで町を一通り回り、スマホで自転車を買ってから、中学生から老後までのステージを順に進んでいく流れを定める。数値・具体的なイベント・ステージの区切りは、本文で「未決定」としたものを確定事項として扱わない。

## 全体の流れ

```text
オープニング（タイトル）
  └─「はじめから」
序章（中学生）
  1. 目覚め　　　　 2階の自室のベッドで目を覚ます
  2. 家の中　　　　 階段で1階へ降り、家族と話すと、母親にスマホを渡される
  3. 町めぐり（強制）町の主な場所をすべて訪れるお使いイベント
  4. 自転車の入手　 スマホで自転車を買う（偽の通販サイトが紛れている）。乗れるようになる
本編（ステージを繰り返す。中学生 → 高校生 → 進学・就職 → 社会人 → 働き盛り → 老後）
  ステージ開始 → 必須イベントが一つずつ解放される。合間は自由に探索・任意イベント
     ├ 必須イベント：前のものを経験すると次が解放される
     └ 任意イベント：見つけた分だけ経験する
  必須イベントをすべて経験 → 節目の解放 → 自室のベッドで「次へ進む」を選ぶ → 節目の演出 → 次のステージへ
最後のステージの後：選んだ出来事を振り返って終わる（その後も町を歩ける）
```

ステージ全体の制限時間はない（[判断記録 0016](../decisions/0016-story-milestone-unlock.md)）。

## 序章

主人公は序章の時点で中学生とする。序章は最初のステージ「中学」の導入にあたる。

### 1. 目覚め（家の2階）

- 「はじめから」を選ぶと、主人公の家の2階にある自室のベッドの上から始まる。画面が明るくなり、主人公がベッドから起き上がる短い演出を入れる。
- 自室には、ベッド・机・窓など、中学生の部屋らしい生活感のある家具を置く。家具の種類と配置は未決定。
- 自室の階段から1階へ降りる。2階は自室のみとするか、他の部屋も置くかは未決定。

### 2. 家の中（1階）：スマホを受け取る

- 1階は玄関・リビング・台所とし、母親がいる。他の家族を置くかは未決定。
- 母親に話しかけると、主人公は母親から [スマホ](phone.md) を渡される。以後スマホを所持し、開けるようになる。受け取る前はスマホを開けない。
- 続けて母親からお使いを頼まれ、序章の「町めぐり」が始まる。
- 母親と話す前に玄関から出ようとした場合は、母親に呼び止められて外に出られない（行き止まりにしない）。
- 母親の台詞、スマホを渡す理由づけ（中学入学の祝いなど）は未決定。

### 3. 町めぐり（お使いイベント・強制）

マップ全体を把握してもらうため、母親に頼まれたお使いとして町の主な場所をすべて回るまで序章を終えない。

- お使いの行き先（チェックポイント）は町の主要施設から選ぶ。候補は学校・駅・公園・商店（コンビニ等）で、最終的な一覧は未決定。マップの施設定義（`facilityId`）に基づいて指定し、描画や移動の処理に場所ごとの条件を書かない。
- 各行き先に用事（例：品物を買う、届け物を渡す、伝言を伝える）を一つずつ置き、行き先の NPC に話しかけて用事を済ませると達成とする。用事の内容は未決定。買う用事は [店員から始める買い物](shopping.md) の画面を使えるようにする。
- 用事は失敗しても達成とみなし、やり直しや詰みを生まない（品物を買い間違えても、渡す・伝える会話の結果は状態に反映するだけ）。
- 未達成の行き先は、画面の案内（残りの件数と次の行き先の名前）と [ミニマップ](map.md) の印で示す。達成済みの行き先は印を変える。順番は自由とする。お使いの一覧をスマホで確認できるようにするかは未決定。
- お使いの間に任意で建物に入ったり、NPC と話したりしてよい。お使いの途中ではセキュリティイベントを発生させない（導入の負担を減らすため。例外を設けるかは未決定）。
- この段階では自転車に乗れない（歩き・走りのみ）。
- 全件を済ませると、自宅に戻るよう案内する。

### 4. 自転車の入手（スマホで購入・偽サイトのイベント）

- お使いを終えて自宅に戻ると、自転車をスマホの通販で買う流れになる（きっかけの会話は未決定）。
- この購入は序章で必ず経験するセキュリティイベントとし、題材は [SEC-002：自転車を買うときの偽通販サイト](../events/security-events.md) を使う。複数の通販サイトを比較し、その中にセールで安く見える偽サイトが紛れている。
- 偽サイトで買った場合も行き止まりにしない。偽サイトの見分け方と被害の影響（所持金の減少など）を伝えたうえで、最終的に自転車を入手して序章を終える（入手の手段は未決定。正規サイトで買い直す、家族に相談して買ってもらう等）。
- 正しく見分けられたかは序章の達成条件にしない。選んだ結果と履歴は [状態](player-state.md) に残し、後のイベントの条件に使える。
- 購入に使う所持金の出どころ（お小遣い、お使いの駄賃など）、サイトの数・価格・画面の見せ方は未決定。SEC-002 の詳細化は [イベント文書](../events/README.md) で行う。
- 入手以降、屋外で [自転車](bicycle.md) に乗れるようになる。入手前は乗車操作を受け付けず、操作ヒントも出さない。
- 自転車を入手した時点で序章を終え、最初のステージ「中学」の本編を開始する。

## 本編：ステージ進行

### ステージ

- 人生を「ステージ」に区切って進める。ステージは学校段階などの区切りで、最初のステージは中学とし、「中学 → 高校」のように順に進む。
- ステージは [全体企画書](../product.md) の年代（子ども・学生・成人・中年・高齢）を細かく分けたものとする。高校以降のステージの一覧（どこで区切り、どこまで続けるか）は未決定。
- 中学から始めるため、幼少期・小学生の時期を本編で遊ぶかどうか（回想・省略など）は未決定。現在の試作マップ・教室・サンプルイベントは幼少期向けであり、中学に合わせた差分が必要になる。
- ステージの切り替えで、町の差分（[マップと探索](map.md) の年代差分）、NPC、受けられるイベントが変わる。

### 人生ゲーム式の進行

- ステージ中、プレイヤーは町を自由に移動し、場所・人・物に関わってイベントを経験する。イベントで選んだ結果は所持金・能力・交友などの [状態](player-state.md) に反映され、後のイベントの発生条件になる。
- すごろくのように「次に起きる出来事」へ進んでいく感覚を出すため、ステージごとに出来事の流れ（必須イベントの順番）を用意し、その合間を自由行動で埋める。
- イベントの仕組みは [イベント基盤](life-events.md)、個別の内容は [イベント文書](../events/README.md) で扱う。日常とセキュリティの比率（おおむね 7:3〜6:4）はステージ単位でも目安とする。
- 序章で渡したスマホを、本編のイベント（メッセージ・通販など）のきっかけに使える。

### 必須イベントと節目

各ステージに、そのステージを代表する必須イベント（入学・進路・就職など）を置く。

- 必須イベントは定義順に一つずつ解放する。前のものを経験すると次が解放される。
- きっかけは次のどちらかとし、イベントごとに定義する。
  - **場所**：決まった場所（エリア）に入ったとき。画面の案内とミニマップの印で場所を示す。
  - **その場**：解放されてから、探索中の時間が決まった秒数たったとき、その場で始まる（電話・チャット・届いたメールを読む場面など）。時間は会話・選択肢・画面を開いている間は進まない。
- 学校・会社などからの知らせは、解放されたときスマホの受信トレイにメールとして届く。メールを読んだだけでは経験にならず、出来事はその場所で始まる。
- 前のステージの選択で、起きる必須イベントを変えられる（条件に合わないものは飛ばす）。
- 必須イベントの結果（成功・失敗、選んだ内容）にかかわらず、経験したことで達成とみなす。正しいセキュリティ判断や被害の回避を達成条件にしない。序章の自転車購入（SEC-002）も同じ扱いとする。
- 必須イベントをすべて経験すると節目が解放され、自宅をミニマップで示す。解放後も探索でき、自室のベッドで「次へ進む」を選んだときだけ次のステージへ移る。「まだ町で過ごす」を選べば留まれる。
- 各ステージの必須イベントの件数と内容は試作で、採用は未決定。

### 任意イベント

- 必須イベント以外は任意イベントとし、見つけて経験した分だけ結果が残る。経験しなくても次のステージへ進める。
- 任意イベントの発見方法（NPC の頭上の印、スマホの通知など）は未決定。セキュリティイベントだけに目印を付けるような区別はしない（[マップと探索](map.md) の方針）。

### ステージの終わりと引き継ぎ

1. 必須イベントをすべて経験したら、節目の解放を知らせる。
2. 自室のベッドで「次へ進む」を選ぶと、卒業などの節目の演出を表示する。
3. 次のステージを自室から開始する。最後のステージの後は、[最終評価](#最終評価issue-62) を表示して終わる。

所持金・能力・持ち物（スマホ・自転車を含む）・交友・過去の選択は次のステージへ引き継ぐ。

### ステージの一覧（試作）

区切りは Issue #85 の案をもとにした仮のもの。中身・件数・金額は `game/src/story/config.ts`・`events.ts` にあり、採用は未決定。

| ステージ | 必須イベント（試作）。（被害時）は前の選択で被害が出たときだけ起きる対処の出来事 |
|---|---|
| 中学生 | 入学式 → 部活 → ゲームのアカウント（セキュリティ）→（被害時）乗っ取られたアカウント → 志望校 → 高校入試 |
| 高校生 | 入学式 → 部活の大会／文化祭の展示／初めてのアルバイト（中学の部活で変わる）→ 文化祭の写真（セキュリティ）→（被害時）知らない人からのメッセージ → 卒業後の進路 |
| 進学・就職 | 大学の新生活／初出社とパスワード（進路で変わる）→ カード会社を装ったメール（セキュリティ）→（被害時）身に覚えのない請求 → 就職活動／仕事の失敗 |
| 社会人 | 拾ったUSBメモリ（セキュリティ）→ 見知らぬログイン（セキュリティ）→（被害時）乗っ取られた通販アカウント → 喫茶店での約束（結婚） |
| 働き盛り | 昇進／セキュリティ研修（USBメモリの判断で変わる）→ 子どものゲーム課金／趣味の仲間（結婚で変わる）→ 振込先の変更（セキュリティ）→（被害時）だまし取られたお金 → 親のこと |
| 老後 | 昔の友達 → 還付金の電話（セキュリティ）→（被害時）振り込んでしまったお金 → 健康相談 → 孫とスマホ |

分岐：日常の選択（部活・進路・結婚）と、セキュリティの選択（被害が出たか・対処したか）の両方で、後の出来事・仕事・家族・所持金が変わる。社会人・働き盛り・老後の始まりには、仕事や年金の収入（仮値）が入る。

セキュリティの題材は [SEC 候補](../events/security-events.md) と [叩き台](https://github.com/kame447/gmo-security-life-game/blob/docs/story-stage-proposals/docs/events/stage-event-proposals.md) から仮に置いたもので、SEC 候補の採用・年代を決めるものではない。

### 最終評価（Issue #62）

[Issue #62](https://github.com/kame447/gmo-security-life-game/issues/62) の設計に沿って、評価を「日常」と「セキュリティ」の2軸に分ける。計算は `game/src/story/score.ts`。

- 日常軸：お金（増えるほど1円あたりの伸びが小さくなる）・つながり・成長。
- セキュリティ軸：判断（選択肢ごとの安全／ふつう／危ない）・被害（実際に被害が出たか）・対処（被害のあとに相談・連絡・手続きをしたか）。
- ストーリーの各選択肢に、お金・つながり・成長の増減と、判断・被害・対処、振り返りの一文を持たせる。お金の増減は選んだときに所持金へ反映する。
- スコアは保存せず、保存した選択の履歴と所持金から都度計算する。
- 見せ方：合否ではなく振り返り。各軸の点数（0〜100）と内訳、日常の歩み、セキュリティでは「あのとき何を選び、どうなったか」を一つずつ並べる。
- **仮置き**：結果画面はまだないため、文言だけを会話欄に「人生の振り返り」として出す。各要素の重み・お金の式・満点の基準は #62 で未決定のため、`SCORE_TUNING` に仮値（重みはすべて等しい）を置く。称号は未決定のため出さない。

### 仮置きの場所

専用のマップがない場所は、既存の場所で代用している（`story/config.ts` の `STORY_PLACES` で `provisional` を付けたもの）。マップができたら `areaIds` と `facilityId` を差し替える。

| 場所 | 仮置き |
|---|---|
| 高校 | 隣町（`town-neighbor`）に着いたら始まる |
| 大学 | 隣町に着いたら始まる |
| 会社 | 隣町に着いたら始まる |
| 病院 | くすりや（`shop-pharmacy-interior`）で代用 |

## 家の2階

- 主人公の家は1階と2階の二つの屋内エリアに分け、階段で行き来する（[マップと探索](map.md) の「階段」による遷移）。
- 1階：玄関・リビング・台所。玄関から屋外へ出る。2階：主人公の自室（ベッドがある）。
- 階段は、乗ると遷移先の階の階段の横に、決まった向きで出る。
- 現在の試作の自宅（`home-family-interior`、1フロアにリビング・寝室・台所）を、1階と2階に分けるか、2階を追加するかは実装時に決める。エリア ID は未決定（例：`home-family-1f`・`home-family-2f`）。
- 2階も自宅の一部として扱い、[通信容量](phone-data-budget.md) の「自宅内では減らさない」判定に含める。
- ステージが変わったときの家の差分（部屋の家具、一人暮らしへの転居など）は未決定。

## 保存と再開

- 序章の進み具合（目覚め済み、スマホの受け取り、お使いの達成済みの行き先、自転車購入イベントの結果と自転車の入手）、現在のステージ、経験した必須イベント、その場で始まる出来事までの経過時間、ストーリーで選んだ選択肢を保存する（`story` 欄、v2）。制限時間があった v1 の保存は、同じステージの始めから再開する。
- 「つづきから」では保存した場所・状態から再開する。会話や演出、自転車の購入画面の途中で中断した場合は、その出来事の開始前の状態から再開する。
- 保存の形式は保存基盤（[所持金とバッグ](inventory.md)、[Issue #20](https://github.com/kame447/gmo-security-life-game/issues/20)）とスマホの保存（[スマートフォン](phone.md)）に合わせる。

## 実装の分け方（案）

小さな単位で順に実装し、それぞれで受け入れ条件を確認する。

| 順 | 内容 | 主な受け入れ条件 |
|---|---|---|
| 1 | 家の2階と階段 | 1階と2階を階段で往復でき、2階の自室にベッドがある |
| 2 | 序章の状態と目覚め | 「はじめから」で2階のベッドから始まり、母親と話すまで外に出られない |
| 3 | スマホの受け取り | 母親と話す前はスマホを開けず、話した後は開ける |
| 4 | お使い（町めぐり） | 未達成の行き先が案内とミニマップに示され、全件達成で自宅へ戻る案内が出る |
| 5 | 自転車の購入（SEC-002） | スマホで複数のサイトを比較でき、どれを選んでも最終的に自転車を入手する。入手前は乗れず、入手後に乗れる |
| 6 | ステージと節目 | 中学から始まり、必須イベントをすべて経験するとベッドで次のステージへ進める（0016 で変更） |
| 7 | 必須イベント | 場所・その場のきっかけで、定義順に一つずつ解放される |
| 8 | 保存・再開 | 序章・ステージ・経過時間・経験済みイベントが再開後も保たれる |

実装時は、オープニングから本編への接続、保存、スマホ、自転車、ミニマップ、イベント基盤など、他の作業中ブランチと重なるファイルが多い。着手前に `node scripts/scope-guard/cli.mjs check` で確認し、担当者と調整する。

## 実装状況（試作）

`feat/story-flow`・`feat/story-full-life` の試作。数値・行き先・ステージ・必須イベントの中身はすべて仮で、上の未決定事項を確定させるものではない。

- 開始：タイトル画面の「はじめから」で新しく序章から始まる（保存は先に消える）。「つづきから」は保存から再開し、保存に `story` 欄があれば序章・ステージの続きになる。開発用に `?skipOpening=1&story=1` でもタイトルを飛ばして序章を始められる。`?skipOpening=1` だけのときは、これまでどおり保存（無ければ自由に歩ける状態）から始まる。
- 家の2階：自宅の1階（`home-family-interior`）はそのままにし、2階（`home-family-2f`、自室・ベッド・机）と階段を追加した。階段で移ると、遷移先の階段の横に出る。
- 目覚め：2階のベッドの横から、画面の明転と独り言で始まる。起き上がる動きの演出はまだない。
- 玄関：母親と話す前は玄関（`home-exit`）を通れず、呼び止める台詞を出す。
- スマホ：母親と話すと渡され、以後開ける。受け取る前は開けない。
- お使い：行き先は学校の先生・コンビニ・公園の友達・駅員の4件（仮）。学校・公園・駅は、行き先の NPC に話しかけると決まった会話で達成する。
  - コンビニは「ノートを1冊買う」用事とし、店員に話しかけて開く [店員から始める買い物](shopping.md) の画面で買う。ノートが持ち物に入り、画面を閉じたら達成とする。品ぞろえ・値段（ノート160円）は買い物の画面のものをそのまま使う。
  - 代金として、母親がスマホと一緒にお使いのお金（200円、仮値）を渡す。所持金が値段に足りないときは、店員が会話でノートをくれて達成とし、行き止まりにしない。
  - 画面の案内に残り件数と次の行き先を出す。[ミニマップ](map.md) では、まだの行き先の施設に黄色の輪と「!」を出す。小さい地図の外にある行き先は地図の端に寄せて示す。済んだ行き先には緑のチェックを出す。全件済んだら自宅に印を出す。印を付ける施設は `story/config.ts` の `facilityId` で指定する。
- 自転車の購入（SEC-002）：お使いの後に母親と話すと始まる。スマホの通販画面ではなく、[イベント基盤](life-events.md) の選択肢で3つのサイト（正規・予算超過・偽のセール）から選ぶ。正規サイトでは予算の釣り銭が所持金に入る。偽サイトを選ぶと自転車が届かず、母親が見分け方と相談の大切さを説明した後、残りの予算で町の自転車店で買って自転車を入手する（釣り銭なし）。予算・価格は仮値。入手前は自転車に乗れない。
- ステージ（2026-11-27、判断記録 0016）：中学生から老後までの6つ。制限時間はない。画面上部にステージ名（何番目か）と次の出来事の場所を出し、ミニマップに印を出す。
- 必須イベント：場所とその場のきっかけに対応し、定義順に解放する。すべて経験すると節目が解放され、自室のベッドで次へ進む。老後の後は振り返りの台詞を出して自由に歩ける状態になる。中身と能力値は仮で、採用は未決定。
- メールでの知らせ（2026-11-27、#73 のレビュー）：学校・会社などからの知らせは、必須イベントが解放されたときスマホの受信トレイに届く（通知とホームの未読の印が出る）。会話欄には本文を出さない。差出人・本文は `story/config.ts` のデータに置く。
- 会話の記録（PR #77 のレビューで追加）：母親からのお使いや自転車の選択の会話を読み返せるよう、会話欄に出した台詞と選んだ選択肢を、L キーまたは「かいわ」ボタンで開く画面に一覧する。ストーリーに限らず、すべての会話が対象（詳細は [イベント基盤](life-events.md)）。
- 自宅の1階は、エディタの配置ファイル（`game/data/world/areas/home-family-interior.json`）にも階段と2階への出入口を入れ、ベッドと学習机は2階に移した。階段は出入口と重なるため、エディタでは回せない固定の物として扱う。
- 未対応：自転車の購入をスマホの通販画面（[PR #80](https://github.com/kame447/gmo-security-life-game/pull/80) のウェブ）で見せること、メールのリンクからウェブを開くこと（#79）、任意イベント、仮置きの場所の専用マップ。
- 保存：序章の段階・お使いの達成状況・自転車購入の結果・ステージ・経験済みの必須イベント・選んだ選択肢を保存の `story` 欄に持ち、再読み込み後も続く。
- 確認：`tests/story.test.ts`（老後までの通しプレイを進学・就職の両方で確認）、`tests/world.test.ts`（2階と階段）、`tests/dialog-log.test.ts`、`scripts/e2e-story.mjs`（序章・受信トレイへの知らせ・会話の記録・再開まで9件）。
