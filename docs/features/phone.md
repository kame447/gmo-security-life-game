# ゲーム内スマートフォン基盤

関連: [Issue #22](https://github.com/kame447/gmo-security-life-game/issues/22)、[遊びの進行](gameplay.md)、[判断記録 0006](../decisions/0006-phone-foundation.md)

## 今回の範囲

探索中にスマートフォンを開き、ホームからアプリと画面を開いて戻り、閉じて探索へ戻れる。初期アプリはメッセージ閲覧とゲーム内の擬似 Web で、アプリ・画面・通知・表示内容は独立したデータとして定義する。画面間の移動先はゲーム内 ID であり、実 Web、外部サービス、実アカウントへ接続しない。表示文と通知は動作確認用の架空データで、人物・物語・イベントの採用を意味しない。

起動キー `P` と「スマホ」ボタンはプロトタイプの提案／要検証。探索中だけ開け、会話・外見変更・他のパネルとは同時に操作しない。開いている間は移動・会話操作を止める。画面の「もどる」はアプリ内の前画面またはホームへ戻り、「とじる」または Esc はスマホを閉じる。ボタンはマウス・タッチ、キーボードの Tab と Enter／Space で操作する。

## 所持と保存

基盤検証中は初期所持・使用可能とする。`PHONE_INITIAL_OWNED` と `Game` の初期値指定を分離し、後から進行側が `game.phone.setOwned()` で所持を付与・解除できる。所持解除時に開いていれば閉じる。入手時期・方法や条件評価の実装は未決定で、今回の初期値は物語上の決定ではない。

既存 `slg-map-save-v1` の任意欄 `phone` に形式バージョンと所持状態のみ保存する。開閉、アプリ、表示画面、通知は保存せず、再開時は閉じた状態とする。欄がない旧セーブや欄の不正値は初期所持設定へ戻し、正常な位置・外見を維持する。保存が使えない場合もゲームは続けられる。将来、複数セーブや進行条件、通知の既読・履歴を導入する際は保存設計を改めて定める。

## 今回決めないこと

ストーリー・具体的な人物・各イベントの条件や分岐、アカウント、通知の既読管理、実際のサービス接続は対象外。SNS、偽通知・フィッシング、アプリ権限、オンラインゲーム等との接続や SEC 候補の採否は今後検討する。
