# ゲーム内スマートフォン

対象: [Issue #22](https://github.com/kame447/gmo-security-life-game/issues/22)。画面と操作は2026-11-14の実画面レビューで合格しました。通信容量の設定値や仮の会話内容は未確定で、統合後の回帰検証とmainへのマージは別の確認を経ます。

## 画面候補

端末のホームはアプリアイコンを中心にし、時刻・電波・電池・通信残量をステータスバーへ置きます。390px幅では４列で、アイコンは64〜70px、タップ範囲は44px以上です。メッセージの未読はアイコン上のバッジで示します。メッセージと Web はゲーム内のサンプルで、外部サイトや実アカウントへ接続しません。生活・交流の入口は準備中です。アプリ名や表示内容も暫定で、人物・シナリオを決めるものではありません。

開く・戻る・ホーム・閉じるをクリック／タッチ、またはキーボードで操作できます。P で開き、矢印／Tab で選択、Enter／Space／Z で決定、Backspace で戻る、H でホーム、Esc で閉じます。開いている間は探索入力を止め、会話や別パネル中は開けません。

## メッセージ候補

３人の暫定的な相手を、アイコン・直近のメッセージ・時刻・未読とともに一覧表示します。相手を選ぶと、送受信を左右に分けたスクロール可能な会話が開きます。入力欄で Enter を押すか送信ボタンを操作すると即座に表示され、あらかじめ用意したローカルの返信が続きます。人物名、台詞、返信の間隔はレビュー用であり、ストーリーを採用したものではありません。実際の通信、他プレイヤー、外部 API、AI 会話は使いません。

入力中の文字・方向キーや Esc はゲーム操作へ渡さず、Esc で未送信の文章を失いません。入力は最大280 Unicode code points、制御文字を除去し、送信と受信の文字は textContent で表示します。未読は開いた会話だけ既読になり、一覧とホームの表示に反映されます。送信は `networkAllowed` に従います。返信の経過時間は実行中の時間だけを使い、pause・非表示・終了中は進みません。

`phone.chat` には会話・未読・返信待ちを保存し、旧 v1 に chat 欄がない場合は暫定の初期会話を使います。表示中の画面と未送信の入力は保存しません。履歴は相手ごとに40件、返信待ちは４件、chat全体は256KiBまでに制限します。将来の NPC やイベントはローカルの受信 API へ接続できますが、具体的な人物・イベントは未決定です。

凍結中のバッグ・買い物の旧 codec は新しい chat 欄を保持できません。３機能を通常保存で一緒に使う前に、共通 codec の更新と実際の保存・再読込の確認が必要です。

## メール

対象: [Issue #73](https://github.com/kame447/gmo-security-life-game/issues/73)。画面と操作は2026-11-18に実画面で確認し、合格しました。その後のレビュー（PR #74）を受けて、2026-11-19に一般的なメールアプリに近い画面へ作り直しました。作り直した画面は再確認待ちです。届くメールの中身と時期は暫定です。

ホームの２番目に「メール」アプリを置きます。受信一覧（見出しは「受信トレイ」）は新しい順で、メールを枠で囲まず細い線で区切って並べます。１通ごとに上から「差出人・時刻」「件名」「本文の書き出し」を表示し、未読は青い小さな印と太字で示します。一覧の下に「○件のメール・未読○件」を出します。１通を選ぶと本文を開き、既読になります。本文の画面では、件名の下に差出人の名前・差出人のメールアドレス・宛先・時刻を表示します。戻るで一覧へ、もう一度戻るでホームへ戻ります。未読の数はホームのアイコンにバッジで示します。返信・削除・フォルダ・添付はありません。

スマホを閉じて探索している間にも、メールは届きます。届くとトースト「メールが とどきました（P）」を出します。メールアプリを開いている間はトーストを出しません。

中身は暫定のサンプルで、差出人・件名・本文・届く時期はレビュー用です。人物・イベント・ストーリーを採用したものではありません。最初の１通は初めから受信箱にあり、残りは実際に遊んだ時間（pause・非表示・終了中は数えない）が 30 秒・90 秒を過ぎたあと、次に場所を移ったとき（建物の出入り・駅での移動など）か、スマホを開いたときに届きます。時間を過ぎた瞬間（遊んでいる途中の任意の時点）には届けません。保存や再読み込みのちょうどその時に届いて、保存前と再読み込み後で中身が食い違うのを防ぐためです。将来のイベントは `PhoneModel.deliverMail({ id, from, subject, body, atMs })` で届けられ、同じ ID は二重に届きません。差出人・件名・本文は textContent で表示し、制御文字を除きます。本文の改行は段落として残ります。

差出人の表示名（`from`）とメールアドレス（`fromAddress`）は別のデータとして持ちます。宛先（`to`）を省くと「自分」と表示します。リンクは `links: [{ label, href }]` で、本文に見える文言（`label`）と実際の行き先（`href`）を別に持ちます。リンクを選ぶと「実際のリンク先」として `href` を表示し、「Webで開く」でゲーム内のページへ進めます。ページ履歴を戻ると、元のメールへ戻ります。将来のフィッシングメール等で、見た目と中身の違いを確かめられるようにするためです。リンクは本文の後ろに並びます（本文中の好きな位置に置く機能はありません）。アドレスとリンク先は、本物のメールアドレスやサイトにならないよう、予約済みの名前（`.example`・`.test`・`.invalid`）だけを受け付けます。それ以外は、メールは届けたうえでアドレスやリンクを捨てます。実在のメールサービスとはつながりません。

`phone.mail` には受信箱・既読・届く前のメールを保存します。届く前のメールの残り時間は、前のメールが届いた時点の値を保存します（届くまでの間はセーブの内容が変わらないようにするため）。再読み込みすると、その時点から数え直します。受信箱が変わるまでは mail 欄を書かず、旧セーブに mail 欄がない場合は最初の受信箱から始めます。保存は 50 通・128KiB まで、件名 40 文字・本文 1000 文字・アドレス 64 文字・リンク 1 通 4 件までに制限します。アドレスを持つ前のセーブは、アドレス・宛先・リンクが空のまま読み込みます。

未決定事項：届くメールの中身と時期、イベントとのつなぎ方、フィッシングかどうかを見分ける操作（リンク先を表示する仕組みだけあり、判定や結果はない）、返信や削除、通信残量との関係（今は残量がなくても届き、読めます）。

## ウェブの検索

対象: [Issue #79](https://github.com/kame447/gmo-security-life-game/issues/79)（PR #80、画面レビュー待ち）。本物のインターネットは検索しません。ゲーム用に用意した架空のページだけを検索・表示し、外部とは通信しません（利用者の決定、2026-11-19）。

検索の画面は、一般的な検索サイトに似せます。検索サイトの名前は、「ググる」にちなんだ仮の名前 **Guguru** です（色ちがいの文字のロゴ。利用者の提案、2026-11-20。正式名は未決定）。

ウェブを開くと、ロゴと丸い検索欄、その下に「Guguru 検索」と「運だめし」のボタンが出ます。「運だめし」は、検索して１番目の結果のページをすぐ開きます（戻ると結果の一覧）。検索欄の × で入力を消せます。言葉を入れて検索すると、上に小さなロゴと検索欄、「すべて」の見出し、その下に結果の件数と一覧を出します。結果は１件ずつカードで、サイト名（なければホスト名）と頭文字の丸い印、アドレス（`https://ホスト › パス` の形）、ページ名、説明の１行を並べ、説明の中の検索した言葉を太字にします。結果がなければ「「言葉」に一致する情報は見つかりませんでした。」と検索のヒントを出します。言葉は、ひらがな・カタカナ・半角／全角・大文字／小文字の違いを区別しません。空白で区切った言葉は、すべてを含むページだけが見つかります。ページ名に当たったものを先に並べ、結果は 10 件までです。

結果を選ぶとページを開き、上のアドレス欄に、そのページのアドレスを表示します。ページのリンクは、見えている文言と実際の行き先を別のデータとして持ちます。リンクを選ぶとその行き先のページを開き、ゲームの中にないアドレスなら「ページが見つかりません」とアドレスを表示します。本物のページへは移動しません。戻るで、ページ → 結果 → 検索欄 → ホームの順に戻ります。ウェブを出ると、検索と閲覧の状態は消えます（保存しません）。

ページのアドレスとリンク先は、メールと同じく予約済みの名前（`.example`・`.test`・`.invalid`）だけを受け付け、それ以外は捨てます。町の案内5ページに、序章の自転車通販3店の商品・会社案内ページをローカルで追加しています（`game/src/data/web-prototype.ts`、`bicycle-web.ts`）。通販の流れと未確定の価格は[ローカル実装の買い物と通販](local-commerce.md)を参照してください。検索欄では文字・Backspace・矢印がそのまま入力に使われ、Escape・Enter・Tab だけがスマホの操作になります。通信残量がないときは、既存のウェブと同じく検索もリンクも使えず、「通信残量がありません」と出します。

未決定事項：怪しいサイト・偽サイトなど、検索結果に混ぜるセキュリティの出来事（`docs/events/` の候補はすべて未採用。混ぜられる作りだけ用意）、検索や閲覧で使う通信量、閲覧履歴・ブックマーク・入力の保存、どのページを用意するか。

## 所持と通信

基盤段階の初期所持は設定で切り替えられ、入手時期・方法は未決定です。[ストーリーの流れ](story.md) では、序章で中学生の主人公が母親から渡され、受け取る前は開けない案を提案中です（合意待ち・未実装）。序章ではお使いの後、スマホの通販で自転車を買います。自宅外で開いている間は通信残量が経過時間に応じて減り、自宅内では減りません。所持・開閉・場所・表示状態・pause と保存の境界で計算を更新します。保存されるのは所持状態と残量で、開いている画面やサンプル通知は復元しません。

上限、消費速度、補充、枯渇時の制限、pause・非表示・ゲーム終了中の扱いは未決定です。設定項目、暫定値、旧保存と不正値の扱いは[通信容量](phone-data-budget.md)を参照してください。ステータスバーの時計はレビュー用の端末時刻で、ゲーム内時間の仕様を決めるものではありません。

## 確認方法

`game/scripts/shots-phone.mjs` はホーム・一覧・会話・送信後・返信後などをデスクトップ・縦長・横向きで撮影し、`SLG_SHOTS` だけへ保存します。`game/scripts/video-phone.mjs` は会話を含む遷移を `SLG_VIDEOS` へ録画します。`game/scripts/e2e-phone-simple.mjs` は端末の開閉と入力隔離、所持・残量の保存、小画面の寸法を確認し、`game/scripts/e2e-phone-chat.mjs` は会話の送受信・未読・保存・タッチ・文字列の安全な表示を、`game/scripts/e2e-phone-mail.mjs` はメールの一覧・本文・既読・届いたときのトースト・保存・キーボードとタッチの操作・文字列の安全な表示を確認します。`SLG_URL` は対象の開発サーバーです。画面の品質や採用はスクリーンショットと実操作のレビューで判断します。

レビュー専用の `?review=1` は既存のセーブを読まず、ゲームの自動保存も書き込みません。通常 URL は位置・外見・資産・スマホを同じ v1 セーブへ保存し、位置が不正でも有効な他の欄を保持します。
