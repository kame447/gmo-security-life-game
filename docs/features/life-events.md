# イベント基盤（会話・選択肢・状態変化）

状態：試作（PoC）。[イベント共通仕様](events.md) の「状況 → 選択 → 結果 → 状態への影響 → 後の分岐」を、個別イベントの内容から独立した仕組みとして実装したもの。設計と後続実装の管理は [Issue #18](https://github.com/kame447/gmo-security-life-game/issues/18)。

## 実装済みの範囲

- **きっかけ**：NPC・物に話しかけたとき。各NPC・物の `eventKey` に一致し、発生条件を満たすイベントがあれば、既定の台詞の代わりにそのイベントを始める。なければ既定の台詞のまま。
- **流れ**：導入の会話 → 問いかけと選択肢 → 選んだ結果の会話。選択中は移動・会話送り・地図・みためを止め、選ぶまで探索に戻らない。どの選択肢を選んでも行き止まりにならない。
- **状態への影響**：数値の加算（`stat`）と目印（`flag`）。選んだ内容は履歴に残す。
- **後の分岐**：「経験したか」「何を選んだか」「目印」を、後のイベントの発生条件にできる。
- **発生回数**：既定では一度だけ。経験済みのイベントは既定の台詞に戻る。
- **中断**：選択中に「さいしょから」を押すと、経験として記録せずに中断する。次に話しかけると再び発生する。
- **定義の検証**：起動時に定義の不備（id の重複、選択肢が 1 つだけ、存在しないイベント・選択肢を参照する条件など）を検出し、起動を止める。
- **操作**：キーボード（↑↓／W・S、Z・Space・Enter、数字キー）、マウス、タップ。スマホ幅では選択肢を会話欄の上に全幅で表示し、タッチ操作のボタンを隠す。

## 仮のサンプル（幼少期・採用未決定）

基盤の動作確認用。内容・年代・数値は未決定で、[セキュリティイベント候補](../events/security-events.md) SEC-001〜015 の採用を決めるものではない。

| ID | 種類 | きっかけ | 内容 |
|---|---|---|---|
| `sample.park-play` | 日常 | 公園の「ともだち」 | 何をして遊ぶかを選ぶ。遊ぶと仮の `friendship` が増える |
| `sample.tablet-ad` | セキュリティ | 家の「かぞくのタブレット」 | 「おめでとう！タップして」の広告に、親に聞く／タップする／閉じる |
| `sample.tablet-ad-followup-*` | セキュリティ | 家の「おかあさん」 | 広告で選んだ内容によって、後でかける言葉が変わる |

## 未対応・未決定

- **保存**：イベントの状態は保存せず、再読み込みで初期化する。保存・復帰の形式（`LifeState` の JSON）は用意済みで、[Issue #20](https://github.com/kame447/gmo-security-life-game/issues/20) の保存基盤に合わせて接続する。
- **所持金・持ち物の増減**：#20 の担当範囲のため未対応。
- **状態の項目と値の範囲**：能力・交友などの項目名、値の範囲、画面への表示方法は未決定（`friendship` は仮）。
- **ほかのきっかけ**：建物への出入り、エリアへの入場、主要タスク・年代移行との連動は未対応。
- **イベントの内容**：採用するイベント、年代の配分、日常とセキュリティの比率の管理方法は未決定。
