# 店員との会話から買い物をする

状態：2026-11-13の利用者指示に基づく [Issue #21](https://github.com/kame447/gmo-security-life-game/issues/21) の試作。旧PR #27は未マージで取り下げ、屋外や棚から商品一覧を直接開く導線と旧UIは採用しない。見た目は **提案／要検証・利用者レビュー待ち**。レビュー前には新PRを作らない。

## 体験と操作

店内で店員に話しかけると、NPC担当が定義した既存の挨拶を表示する。「話をきく」で読み進め、「買い物をする／やめる」を選ぶ。買い物を選ぶと、画面下部の会話枠に連続して商品一覧・詳細を広げる。商品アイコン、名前、種類、説明、価格、所持金、所持数と上限を確認し、「この商品を選ぶ」で購入確認へ進む。購入は1回1個。価格と購入後の残高を見て「購入する」で確定する。

結果は店員の会話として伝える。残高不足・個数上限では資産を変えず理由を示す。「ほかの商品を見る」で一覧へ戻り、「店内へ戻る」で終了する。話しかける前と同じ店内の位置で探索を続ける。

| 場面 | キーボード | クリック・タッチ |
| --- | --- | --- |
| 挨拶 | Z／Enter／Spaceで進む、Escで終了 | 「話をきく」 |
| 買う／やめる | 矢印／WASDで選び決定 | 選択肢を押す |
| 一覧 | 矢印／WASDで選び決定、Escで会話へ戻る | 商品を押して詳細を確認し「この商品を選ぶ」 |
| 確認 | 選択肢を選び決定、Escで取消 | 「購入する」／「やめて 一覧へ」 |
| 結果 | 決定／Escで店内へ戻る | 「ほかの商品を見る」／「店内へ戻る」 |

Tab／Shift+Tabで操作対象へ移動する。フォーカスされたボタンの決定キーはそのボタンの処理を優先し、取消で購入しない。キーリピートは無視し、確定後の同じ処理では二重購入しない。

配色・枠・余白・文字・カーソル・コード生成アイコンは仮案。デスクトップと小画面の画像と実操作を利用者がレビューして決める。テスト成功を視覚品質の合格とは扱わない。第三者素材は使わない。

## #33とのデータ契約

室内・出入口・NPCの配置は [#33](https://github.com/kame447/gmo-security-life-game/issues/33) の担当で、本試作は変更しない。[了承済みの提案](https://github.com/kame447/gmo-security-life-game/issues/33#issuecomment-6850312027) に従い、`data/stores.ts` に `{ storeId, interiorAreaId, entrancePortalId, clerkEventKey, catalogId }` を分離する。#33担当は店内追加時にこのデータを追加する。カタログは #21 が `data/shop-catalogs.ts` で管理し、将来店舗の正式IDはマップ／NPC担当が決める。

既存接続は `shop-konbini` / `shop-konbini-interior` / `konbini-enter` / `shopping.konbini.clerk` / カタログ `konbini`。室内エリアIDとイベントキーが一致し、対象がNPCの場合だけ開く。挨拶は対象の既存 `name`・`lines` をそのまま使い、上書きしない。選択肢と購入確認・結果だけを売買側の暫定文言として追加する。

棚の `shopping.konbini.snacks`・`shopping.konbini.drinks`、屋外の `shopping.candy`・`shopping.vending` では既存会話だけを表示し、買い物画面は開かない。自販機の独立サービスは今回の対象外。未配置店舗の検証は、通常マップへ追加しないテスト用室内と `test.shopping.clerk` の仮会話を使う。

## 入力・取引・保存

DOM・CSS・アイコンは `ClerkPanel` が自己マウントし、`index.html` には追加しない。共通 `UiController.registerPanel` へボタンなしのshopとして登録する。会話や別パネルからは開かず、表示中は共通基盤が移動・会話・外見・バッグ・スマホへの入力を遮断する。閉じると入力を解除しマップへフォーカスを戻す。

内部の原子的取引だけを旧実装から再利用する。#20の `game.assets.apply({ moneyDeltaYen, itemDeltas })` を1回呼び、代金と商品を同時更新する。失敗時は全体不変。成功後は既存v1のassets欄を即時保存し、独自欄を増やさない。会話途中は保存せず、再読込では閉じた状態で店内へ復帰する。

暫定例はおかし50円、水120円、ノート160円。上限はおかし・水20、ノート99。商品・価格・説明・初期資金・上限はシナリオやバランスの確定ではない。購入は日常行動でセキュリティの正解を問わない。まとめ買い・売却・在庫・購入履歴は未決定または対象外。

## 検証

Vitestは挨拶から確認までの遷移、取消・残高不足・個数上限・連打・原子的更新・保存復帰、店内/店員の契約、仮会話、共通モーダルとの接続を確認する。

`scripts/e2e-clerk.mjs` は実際に既存入口から入店して買い物・店内復帰・再読込を確認し、屋外/棚から開かないこと、Tab取消、リピート、390×720タッチも検証する。既存探索E2Eは店員の応答だけ新しい挨拶画面へ合わせ、他の会話とSUMMARY13項目は維持する。

`scripts/shots-shop.mjs` は `SLG_SHOTS` のみへ、1280×800と390×720の挨拶・選択・詳細・確認・成功・店内復帰・残高不足・テスト用空カタログを保存する。位置・残高・所持数・空カタログのfixtureはブラウザ内だけで設定し、マップ/NPCソースは変えない。撮影とE2Eは親のsandbox外環境へ依頼する。手順と結果は [game/README.md](../../game/README.md) に記録する。
