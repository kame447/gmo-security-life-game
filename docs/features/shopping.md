# 店員から始める買い物

[Issue #21](https://github.com/kame447/gmo-security-life-game/issues/21) の画面候補。店内で店員に話しかけ、会話→商品選択→確認→購入→同じ店内へ戻る流れを共通とする。配色・配置・数量操作は**候補（未採用）**であり、利用者が画像と実ゲームを比較するまでPR作成・完成扱いをしない。

## 共通の流れとデータ

既存コンビニに入り、店員に向いて決定すると、既存の店員名と挨拶に「買う／やめる」が付く。複数行の会話は順に進める。商品行の選択だけでは支払わず、「選ぶ」から確認へ進む。確認画面で商品・数量・合計・所持金・購入後の残高を照合し、「購入する」で取引する。結果は短い店員の応答として示し、店内へ戻る。挨拶や選択・確認の段階で取り消しても資産は変わらない。

接続は `data/stores.ts` の店内エリアID・店員イベントキーを使う。現存コンビニ1件のみで、屋外の店先・自動販売機・棚・別室では購入画面を開かない。店員やマップの定義は変更しない。他店の店内化と配置は #33 の範囲とする。

商品と単価は `data/shop-catalogs.ts`。比較用の暫定値は水120円、ノート160円、えんぴつ80円。品ぞろえ・価格・初期所持金・個数上限はシナリオの本採用値ではない。商品定義、共通の比較資産、資産API・保存の核は #20 と共有する。

`shop/purchase.ts` は資産ポートの `apply({ moneyDeltaYen, itemDeltas })` を1回だけ呼ぶ。所持金と所持品は同時に変わり、失敗時は両方とも変わらない。`ClerkFlow` は確認段階でだけ購入を受け付け、結果へ進んだ後の再確定は受け付けない。成功時は通常の保存処理を直ちに呼ぶ。

## レイアウト比較（候補・未採用）

| 観点 | `?shop=split` | `?shop=compact` | `?shop=dialog` |
| --- | --- | --- | --- |
| 配置 | 中央の枠。商品一覧と選択中の詳細を左右に置く | 下寄せの枠。商品一覧と選択詳細を縦に集約する | 下部の店員会話枠が継続し、商品・所持金・選択肢が別の窓に出る |
| 商品情報 | 商品名・単価を一覧に並べ、右にアイコン・説明・所持数 | 商品名・単価を行で追い、下に選択中の短い説明・所持数 | 右の商品窓に名前と単価、下部の会話枠に選択中の説明 |
| 選択 | 行全体の色とカーソル。フォーカス枠も表示 | 同じ選択・フォーカス規則で、横幅を一覧に使う | 同じカーソル規則。商品選択と確認で右の窓の内容が替わる |
| 所持金 | 見出し右側に固定 | 同じ位置 | 左上の独立した窓 |
| 数量・確認 | 確認段階で数量、合計、購入後を集約 | 同じ内容・同じ操作 | 会話枠を維持し、確認用の窓へ切り替える |
| 不足 | 不足額を店員の短い応答で示し、購入ボタンを無効化 | 同じ条件・同じ文言 | 同じ条件・同じ文言 |
| 縦長画面 | 一覧と詳細を縦に並べる | 1列を保ち、下寄せの位置との違いを比較する | 会話枠の上に商品・確認の窓を重ねる |

全候補で、角のある枠・等幅文字と日本語ゴシック・濃緑と生成りの配色、矩形を基本にしたアイコンを比較用に用いる。枠や色、文字の見せ方も未採用。

全候補で数量の増減を比較できる。操作範囲は1〜99、かつ所持品の残り枠までとし、所持金に足りる数へ自動で変更しない。不足時は不足額を示す。まとめ買いの本採用・上限や売却、購入履歴、店の在庫は未決定。数量ステッパーは比較用に動作させるが、正式な販売方式を決めるものではない。

### 入力

- 商品一覧は上下／W・Sで選択。確認画面は左右／A・Dで個数、上下／W・Sで購入・戻るを選ぶ。
- Z／Enter／Spaceで決定。フォーカス中のボタンがあれば、そのボタンだけを実行する。取消や閉じるを指しているときに購入へ振り分けない。
- Escは確認から一覧、一覧から会話、それ以外は店内へ戻る。Tabは表示中の有効なボタン内を移動する。
- 商品行・個数の＋／−・決定・戻るをクリック／タッチで操作できる。商品行は選択だけで、購入は別のボタンで確定する。
- パネル中は共通モーダル基盤が移動・通常会話・外見・他パネルの起動入力を隔離する。画面を閉じるとマップへフォーカスを戻す。

## 比較専用の一時セッション

URLのクエリ切替はレビュー専用。

```text
http://127.0.0.1:5182/?shop=split&review=1
http://127.0.0.1:5182/?shop=compact&review=1
http://127.0.0.1:5182/?shop=dialog&review=1
```

`review=1` は既存セーブを読まず、#20と同じ一時資産（2,480円、ノート2・えんぴつ12・水3など）で起動する。既存コンビニ内の、入口から到達できる店員の隣へレビュー用の主人公を置き、店員の会話から始める。マップやNPCの配置データを変えるものではない。

購入・定期保存・リセット・みための決定・画面離脱を含む保存経路を止め、通常セーブは変更しない。レビュー画面で買ったものは再読込時に比較用の初期状態へ戻る。`review=1` がない通常起動は、探索からの入店と既存の保存・復帰を使う。

## 検証と撮影

```sh
cd game
npm ci --cache /private/tmp/slg-npm-cache
npm run build
npm test
npm run dev -- --host 127.0.0.1 --port 5182 --strictPort
```

ブラウザ検証・撮影はsandbox外の実行担当へ依頼する。

```sh
SLG_URL=http://127.0.0.1:5182 node scripts/e2e-shop-candidates.mjs
SLG_URL=http://127.0.0.1:5182 node scripts/e2e.mjs
SLG_URL=http://127.0.0.1:5182 SLG_SHOTS=/private/tmp/slg-audit/ui-review/shop-candidates/HEAD node scripts/shots-shop.mjs
```

`e2e-shop-candidates.mjs` は全候補のキーボード・タッチ、入力隔離、数量と確認、取消フォーカス、原子取引、連打・リピート、即時保存・復帰、残高不足・個数上限、小画面の収まり、会話枠の継続とレビュー時の保存隔離を16項目で確認する。ブラウザ内の公開APIで一時的に位置と資産を用意し、実マップやNPCを差し替えない。通常の入店経路は既存 `e2e.mjs` が確認し、店員イベントの分岐だけを新しい会話表示に合わせる。

`shots-shop.mjs` は `SLG_SHOTS` の指定先だけに、1280×800と390×844で、各候補の会話・一覧・選択・確認・取消後・残高不足・購入結果の42枚を出力する。同じ商品・同じ資産・同じ数量で比較する。不足状態だけは同額の一時的な80円を全候補へ与える。アイコンはコード描画。

単体テストは会話の順序、店内NPCへの接続、原子的な購入、取消、不足、上限、複数個の合計、重複確定、保存復帰、共通モーダルの排他とレビュー準備を扱う。ブラウザ実行結果と利用者の採否は、この文書に書いた仕様や単体成功から推定しない。
