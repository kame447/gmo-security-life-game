# 店員から始める買い物

[Issue #21](https://github.com/kame447/gmo-security-life-game/issues/21)。店内で店員に話しかけると、店員の挨拶・商品一覧・所持金を同時に表示する。挨拶のあと、同じ帯がカーソルのある商品の説明に切り替わる。買い物を始めるための追加ボタンや、挨拶を送る操作は挟まない。表示は互いに離れた3つの箱（所持金・商品一覧・説明と会話の帯）に分け、店内・店員・主人公が見えたままにする。

## 流れ

店員へ1回決定するだけで、商品を選べる。挨拶は既存の店員名と、先頭の台詞の最初の1文だけを使う。カーソルを動かすだけでは支払わない。カーソルのある商品で決定すると、下の帯が確認に切り替わり、個数・合計・購入後の残高を確かめて「買う」で確定する。結果は店員の短い応答として同じ帯に表示し、一覧はそのまま続けて使える。

## 画面の構成（2026-11-15に利用者が承認）

3つの箱は、店内の絵が描かれている矩形（表示領域）の中に置く。位置と大きさはその矩形に対する割合で、文字・余白・線の太さはゲームの1ドットの大きさ（拡大率）の倍数で決める。

- 所持金の箱: 上の角。幅は表示領域の30%。1行目にラベル、2行目に右そろえの金額。
- 商品一覧の箱: 所持金の反対側。幅は48%、高さは行の数に合わせ、最大で帯の手前まで。1行に品名（左）と価格（右そろえ、等幅の数字）。見出し・説明・ボタンは置かない。カーソルは行の幅いっぱいの枠1つ。末尾の行「店を出る」で店内へ戻る。行が箱に収まらないときは箱の中でスクロールし、続きがあるあいだだけ下端の中央に下向きの印を出す。
- 説明と会話の帯: 下端、幅いっぱい、高さは22%以上。帯に出すものは一度に1つだけにする。
  - 話しかけた直後: 店員の名前と挨拶だけ（アイコンなし）。
  - カーソルを動かしたとき、商品で決定したとき、または開いてから2秒（`shop-panel.ts` の `GREETING_MS`）たったときの、先に起きたほうで挨拶を終える。以後は、カーソルのある商品のアイコンと説明だけを出し、カーソルを動かすたびに切り替える。
  - カーソルが「店を出る」にあるとき: 帯は空。
  - 確認中: 商品名・所持数・個数の増減・合計・購入後・「買う」「やめる」。2秒の経過では変わらない。
  - 購入後: 店員の応答だけ（アイコンなし）。決定またはカーソルの移動で商品の説明へ戻る。
  - 店を閉じると待ち時間を取り消す。開き直すたびに挨拶から始める。新しい枠は重ねない。
- 左右: 一覧は主人公のいない側に置く（主人公が表示領域の右半分にいれば一覧は左、所持金は右上）。
- 文字は7ドット相当（拡大率3で21px、2で14px。13pxを下回らない）。一覧の行の高さは12ドット相当（拡大率3で36px、2で24px）。タッチできる端末では行を44px以上にする。個数の増減と「買う」「やめる」は常に44px以上。
- 表示領域が画面上で幅392px・高さ320px（幅が420px未満のときは高さ330px）より小さい場合は、表示領域の中心からその大きさまで配置の範囲を広げ、文字の倍率は最大1.75とする。この場合、箱は店内の絵の外にはみ出す。
- 見た目は、淡い単色の面と濃い色の枠。角丸・影のぼかし・グラデーション・半透明は使わない。文字はゲーム本体と同じ書体。
- アイコンは `ui/bag-hotbar/icons.ts`（矩形で描いたドット絵。画像素材なし）を使う。

画面は承認済み。商品・価格は暫定で、実機での検証は未実施。残る実装上の制約: カメラ・拡大率・主人公の位置は、検証用の `window.__slg` を読み取り専用で使って得ている（`main.ts` からレンダラーを渡す形にはしていない）。左右の判定は主人公の位置だけで、店員の位置は見ていない。

接続は `data/stores.ts` の店内エリアID・店員イベントキーを使う。この枝では既存コンビニ1件を対象とし、屋外の店先・自動販売機・棚・別室からは購入画面を開かない。他店の室内・店員・入口は #33 の範囲であり、この画面では配置データを変更しない。

## 入力と取引

- 上下／W・S（左右／A・Dも同じ）でカーソルを動かし、Z／Enter／Spaceで確認へ進む。クリック／タッチは、1回目でその行へカーソルを移し、カーソルのある行をもう一度押すと確認へ進む。支払いは別に確定する。
- カーソルが「店を出る」にあるときの決定、または「店を出る」のクリック／タッチで店内へ戻る。
- 確認中は左右／A・Dや＋／−で個数を変える。上下／W・Sで「買う」「やめる」を選べる。
- フォーカス中のボタンを決定キーで操作すると、そのボタンだけを実行する。取消・閉じるから購入へ振り分けない。
- Escは確認中なら一覧へ戻り、一覧・結果からは店内へ戻る。Tabは表示中の有効なボタンを移動する。
- 購入の直後の決定は、店員の応答を閉じて一覧へ戻るだけで、確認を開かない。
- 開くだけ・選ぶだけ・取消・残高不足・個数上限では資産を変えない。確定キーのリピートで重複購入しない。
- パネル中は共通モーダル基盤で移動・通常会話・外見・他パネルとの入力を隔離する。閉じるとマップへフォーカスを戻す。閉じた次のフレームでは共通入力処理が押下中の入力を消すため、操作復帰のE2Eは1フレーム後に移動キーを押して確認する。

商品と単価は `data/shop-catalogs.ts`、品目定義と資産APIは #20 を共有する。現在の商品・価格・初期資産・数量操作の上限は暫定であり、正式な品ぞろえや販売方式を決めるものではない。

`shop/purchase.ts` は資産ポートの `apply({ moneyDeltaYen, itemDeltas })` を1回だけ呼ぶ。所持金と所持品は同時に更新し、失敗時は両方とも変えない。`ClerkFlow.openShop` は挨拶の内容を保ったまま一覧から開始し、取引は確認段階でだけ受け付ける。成功時は通常の保存処理を直ちに呼ぶ。

通常保存では資産・スマホの所持状態と通信残量・会話履歴・位置・外見を共通のv1データに保持する。スマホの通信時間と返信進行は既存のPhoneModelが担当し、買い物処理はそれを置き換えない。不正な位置を修復しても、有効な他の保存欄は保持する。

## レビュー用の一時セッション

```text
http://127.0.0.1:5173/?review=1&shopReview=1
```

`?shop=`での候補切替は廃止する。`review=1&shopReview=1`では既存セーブを読まず、共通の一時資産で、既存コンビニ内の到達できる店員の隣から買い物画面を開く。`review=1`だけの場合はmain既存のスマホ用レビューを維持し、買い物画面を自動では開かない。マップやNPCの配置は変えない。

購入・定期保存・リセット・みための決定・離脱を含め、通常セーブへの保存を止める。レビュー中の購入は再読込時に初期状態へ戻る。`review=1`がない通常起動は、探索からの入店と既存の保存・復帰を使う。

## 検証と撮影

```sh
cd game
npm ci --cache /private/tmp/slg-npm-cache
npm run build
npm test
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

ブラウザはheadlessでsandbox外の実行担当へ依頼する。

```sh
SLG_URL=http://127.0.0.1:5173 node scripts/e2e-shop.mjs
SLG_URL=http://127.0.0.1:5173 node scripts/e2e.mjs
SLG_URL=http://127.0.0.1:5173 SLG_SHOTS=/private/tmp/slg-audit/ui-review/shop-ui/HEAD node scripts/shots-shop.mjs
SLG_URL=http://127.0.0.1:5173 SLG_VIDEOS=/private/tmp/slg-audit/ui-review/shop-ui/video node scripts/video-shop.mjs
```

専用E2EはPC・390px縦・844px横で、1回の会話開始直後からの選択、カーソル移動で説明が切り替わること、3つの箱の非重複と店員・主人公が隠れないこと、ボタンの中心と四隅の到達性、キーボードとタッチ、取消、原子取引、連打、移動停止と復帰、不足・上限、即時保存と復帰を扱う。通常の購入・定期保存・実pagehide後の資産/phone/chat/位置/外見と、レビュー時の保存隔離も照合する。帯の切り替え（挨拶だけ、2秒後、2秒より前のカーソル移動、確認中と購入後、開き直し、閉じたあと、「店を出る」の行）は、ブラウザの仮想の時計で時間を進めて確かめる。時計で進む返信待ち時間の保持は単体テストで扱い、ブラウザの保存比較には返信待ちがない完了済み会話を使う。

撮影は3サイズで開いた直後・カーソル移動・確認・取消後・不足・購入結果の18枚。録画は3サイズで、店員への1操作からカーソル移動・不足・確定・同じ店内への復帰までを残す。書き込みは指定の出力ディレクトリのみとする。

PR #54のバッグはこの変更に含めない。同じアイコンとレビュー用資産データは同一の内容を共有し、共有する起動処理と文書は先にマージされた側へ追従する。#33を統合する際は店舗データの7件を正本にし、他店舗のカタログを接続する。
