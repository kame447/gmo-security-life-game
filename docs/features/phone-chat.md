# メッセージの既読表示

対象は [Issue #22](https://github.com/kame447/gmo-security-life-game/issues/22) のゲーム内スマホ。2026-11-28の利用者指示に基づき、チャットに送信メッセージの既読表示を追加する。実装と画面は利用者レビュー待ちで、確認前に main へマージしない。端末全体の操作と受信未読の扱いは [スマートフォン](phone.md) を参照する。

## 表示するタイミング

相手の返信が届いた時点で、その返信より前に送ったメッセージの時刻の上へ「既読」を表示する。返信前・返信なしの送信には表示せず、相手から受信した吹き出しにも表示しない。複数のメッセージを続けて送った場合は、返信が届く前までの送信にまとめて既読を付ける。返信の後に新しく送ったメッセージは、次の返信が届くまで未表示のままとする。

判定には、会話に残っているメッセージの並び順を使う。端末時計の変更などで表示時刻が前後しても、その時刻の大小で既読を変えない。会話を開き直したときも、保存された送受信の履歴から同じ規則で表示する。

現在の会話はゲーム内の固定返信を使う試作であり、実際の相手や外部サービスから既読通知を受け取るものではない。固定返信を使い切った後の送信など、新しい返信がない場合は、時間が経っても既読を付けない。相手の閲覧だけで既読になる仕組みや返信前の既読は、今回の対象に含まない。

## 受信の未読と保存

トーク一覧やホームの未読数は、従来どおりプレイヤーがまだ読んでいない受信メッセージの件数とする。会話を開くと、その会話の受信だけを既読にする動作も変えない。送信側の「既読」表示のために受信の未読数を減らすことはない。

既存の `ChatMessage.read` はプレイヤー側の受信未読を扱う値であり、送信では初めから `true` になる。その値を相手が読んだ状態として流用せず、チャット画面が送受信の順序から表示を組み立てる。新しい既読状態やタイマーは保存せず、`phone.chat` の保存形式も変更しない。返信待ちで保存した場合は、従来の残り待ち時間を再開し、返信が届いた後に既読を表示する。

## 確認

`game/tests/phone-chat-receipts.test.ts` で、返信待ちと返信後、連続送信と返信がない場合、保存後の再開、文字列をそのまま表示することを確認する。実際のチャット画面は `game/scripts/e2e-phone-chat.mjs` で操作し、入力・未読件数・再開を含む既存の動作も確認する。実画面の画像と検証結果は [確認資料](../review/phone-chat-read/README.md) にまとめる。
