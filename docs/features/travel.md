# 電車での街間移動（試作／要検証）

[Issue #36](https://github.com/kame447/gmo-security-life-game/issues/36) の候補です。既存の駅の構造は [Issue #35](https://github.com/kame447/gmo-security-life-game/issues/35) と連携します。街・駅・路線の名前、配置、台詞は暫定です。運賃・利用条件・時刻表は定めず、乗車だけで人生の段階を進めません。

## 試す操作

駅舎から改札・ホームへ歩き、案内の前で調べる操作を行います。行き先を選び、別の確認画面で「のる」を押すと到着駅へ移動します。「もどる」または Escape で前の画面へ戻れます。到着駅からは町へ出て探索し、同様の操作で元の駅へ戻ります。選択画面では矢印キー、Enter、Z、タップを使えます。

乗車は指定されたホーム上の位置・向き・案内対象からのみ開始します。線路へ歩いて入ることや、行き先を選んだだけでは移動しません。移動前に出発位置と到着先を再確認し、不正な到着先や自動出入口の上には移動しません。

## 構造と保存

`world/railway.ts` は駅・路線と、到達性検証用の有向辺を提供します。`travel/network.ts` は既存駅の `STATION_ACCESS` と暫定の隣町駅を参照します。街を増やすときはエリアと駅のデータを追加し、路線の駅一覧に登録します。列車の移動を自動ポータルとして表現しません。

`travel/session.ts` は選択・確認後の移動を検証し、`travel/panel.ts` は操作画面を表示します。共有側の配線では到着時に通常のエリア変更通知・入力解除・保存を行う案です。現行mainの保存対象は位置・向き・外見です。所持品、所持金、人生履歴、スマホの状態はそれらを持つ統合版で別途保持を確かめます。

## 現在の確認状況

専用の状態・路線・隣町の単体試験では、位置外や無効な到着先からの移動拒否、明示確認、fixture上の往復と位置・外見の保存再読込を確認しています。#35の実駅と共有入力への接続、実画面の往復・操作性は配線版で検証します。利用者の実画面での確認前に完成扱いせず、PRも作成しません。

配線版が用意できた後、親がsandbox外で実行する例です。ブラウザは独立した一時コンテキストを使います。

```sh
cd game
SLG_URL=http://127.0.0.1:5201 SLG_SHOTS=/private/tmp/slg-audit/train-travel-e2e \
  node scripts/e2e-train-travel.mjs
```

実際の開発サーバーのポートは実行前に確認します。E2Eは元の町から駅へ実際に歩き、乗車・隣町探索・帰路・保存復元を確認し、1280×800・390×844・844×390の画像を出力します。
