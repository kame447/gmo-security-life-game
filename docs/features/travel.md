# 電車での街間移動（試作／要検証）

[Issue #36](https://github.com/kame447/gmo-security-life-game/issues/36) の候補です。既存の駅の構造は [Issue #35](https://github.com/kame447/gmo-security-life-game/issues/35) と連携します。街・駅・路線の名前、配置、台詞は暫定です。運賃・利用条件・時刻表は定めず、乗車だけで人生の段階を進めません。

## 試す操作

1. **改札で行き先を選ぶ（確定は1回）。** 駅の改札の南から上向きに操作すると、行き先の一覧が出ます。行き先を選ぶとそのまま乗車が始まり、確認の画面は出ません。「もどる」で一覧を閉じられます。
2. **自動で乗り込む。** 決定の直後から、入力は受け付けません。主人公が改札を通り、ホームを歩いて、行き先の方向の車両のドアの前へ進み、乗り込みます。列車は駅の構内の線路へ入線して止まり、ドアが開き、閉まって発車します。
3. **列車が駅から出て、隣町の駅へ。** 発車した列車が画面の外へ出た直後に、隣町の駅へ切り替わり、同じ向きから列車が入ってきて止まります。ドアが開き、主人公が降ります。
4. **そのまま改札の外まで自動で出る。** 降りた主人公は、改札の内側まで歩き、改札を通り、改札の外で止まって、そこで操作が戻ります（追加の操作・確認はありません）。操作が戻ったあとも、列車だけがそのまま出ていきます。到着の保存位置は、この改札の外です。

画面全体の黒塗り・暗転・別画面への切り替えは使いません。動きを減らす設定（`prefers-reduced-motion`）では、到着した状態（列車が止まり、ドアが開いている）を0.7秒だけ見せて、操作を戻します。演出のスキップはありません（暫定）。

改札は2タイルとも歩いて通れません。南から上向きに操作すると行き先の一覧（入場）、ホーム側（北）から下向きに操作すると一覧なしで改札の外へ出ます（旧い保存データなどでホーム側に残った場合の救済で、通常の流れでは使いません）。それ以外の向き・位置では開きません。のりばの案内は通常の会話です。駅の構内は単式ホーム1面・線路1本（北端、部屋の左右の端まで連続）で、上りも下りも同じ線路・同じドアの位置を使い、列車の入ってくる側と出ていく側だけが違います。上り・下りは路線の駅順で決まり（増える向きが下り）、下りは右へ、上りは左へ発車します。

位置が変わるのは、出発した列車が画面の外にいる瞬間の1回（到着。保存される位置は到着駅の改札の外）と、ホーム側からの手動の出場の1回だけです。演出中に再読み込みすると、出発前（出発駅の改札の外）か到着後（到着駅の改札の外）のどちらかの整合した状態に戻り、所持品・所持金は変わりません。きっぷや選択は保存しません。到着先が立てない位置などで確定できないときは、位置を変えずに演出を終わります。

## 構造と保存

`world/station-flow.ts` の `getStationFlow(駅ID)` が、駅ごとの改札（前・内側・外の位置）・のりば・ドア・ドアの前・上り下りごとの発車の向きと入ってくる側を持ちます。乗車側は数値を決め打ちにせず、`travel/stations.ts`（読む1か所）経由で読みます。`world/railway.ts` は駅・路線と到達性検証用の有向辺、`travel/network.ts` は既存駅と暫定の隣町駅を登録します。街を増やすときは、エリア・駅・`getStationFlow` のデータを追加し、路線の駅一覧に登録します。列車の移動を自動ポータルとして表現しません。

- `travel/session.ts`: 改札の操作から、行き先の一覧、決定（`choose`）、到着の確定（`commitArrival`）、改札を出る確定（`passExit`）までの状態と検証。きっぷは持ちません。
- `travel/choreo.ts`: 演出の振り付け（描画なし）。歩く経路は、ホームの床だけを通る最短経路（改札を通る区間を足す）です。時刻から、列車の位置・ドアの開き・主人公の代役の位置と向き・位置を確定する瞬間を決める純粋な関数です。列車は、出発側は最後尾が画面の外へ出きった位置、到着側は先頭が画面の外にいる位置から出入りし、切り替えの前後で列車の速さを揃えます。
- `travel/panel.ts`: 一覧の表示と、演出の駆動。実際の主人公は改札の前に置いたまま、`town-train/station-scene.ts` の `stationScene` に列車と主人公の代役を毎フレーム設定し、描画側（`render/renderer.ts`）がマップの上に描きます。エリアの切り替え時のフェードは演出中だけ止めます。
- 位置の移動は、既存の `game.arriveByTrain`（エリア変更の通知と保存を伴う）を使います。現行mainの保存対象は位置・向き・外見です。所持品、所持金、人生履歴、スマホの状態は、それらを持つ統合版で別途保持を確かめます。

## 現在の確認状況

単体試験: 改札の操作の条件（向き・位置・会話中）、決定1回で乗車が始まりメニューが残らないこと、二重の発車・二重の確定の拒否、到着先の拒否（無い・立てない・自動出入口）、共有の到着フックの扱い、往復と保存の復元、振り付け（歩く経路が歩ける床の上、乗り込む位置の連続、改札の外の位置と向きでの終了、位置の確定が1回、暗転の量が無いこと、切り替えの前後の列車の速さ、画面の端での出入り、動きを減らす設定）。

E2E（`scripts/e2e-train-travel.mjs`）: 元の町から駅へ実際に歩き、改札で決定して乗車・発車・到着・下車・探索・帰路まで、1280×800・390×844・844×390で確認します。演出中、毎フレーム、実画面の暗さ・エリアのフェードが出ないこと・列車がマップ上に描かれること・切り替えの前後で列車が見えない時間の長さを記録し、メニューが出ないこと、演出中の入力を受け付けないこと、再読み込み、動きを減らす設定も確認します。`SLG_VIDEO` を指定すると録画も保存します。

```sh
cd game
SLG_URL=http://127.0.0.1:5282 SLG_SHOTS=/private/tmp/slg-audit/train-travel-e2e \
  SLG_VIDEO=/private/tmp/slg-audit/train-travel-video node scripts/e2e-train-travel.mjs
```

実際の開発サーバーのポートは実行前に確認します。利用者の実画面での確認前に完成扱いせず、PRも作成しません。演出の秒数・歩く速さ・加速度は暫定値です。
