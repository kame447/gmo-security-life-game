# 電車での街間移動（試作／要検証）

[Issue #36](https://github.com/kame447/gmo-security-life-game/issues/36) の候補です。既存の駅の構造は [Issue #35](https://github.com/kame447/gmo-security-life-game/issues/35) と連携します。街・駅・路線の名前、配置、台詞は暫定です。運賃・利用条件・時刻表は定めず、乗車だけで人生の段階を進めません。

## 試す操作（2026-11-14 の仕様変更後）

1. **改札で行き先を選ぶ。** 改札を調べると行き先の一覧が出て、選んで「うけとる」を押すときっぷを受け取ります（位置・所持品・所持金は変わりません）。「もどる」「きっぷを かえす」で取り消せます。
2. **ホームののりばへ歩く。** のりばの看板はきっぷの確認だけを行い、行き先は選べません。きっぷが無い場合や、きっぷの方向と違うのりばでは案内が出るだけで、乗れません。「のる」の前までは「もどる」で取り消せます。
3. **乗り込む → 発車 → 到着・下車。** 「のる」を押すと、主人公が車両のドアへ入り、ドアが閉まり、町を走る列車と同じ描画の車両が駅を出ます。暗転の切れ目で到着駅へ移り、車両が入ってきて止まり、下車して操作が戻ります。演出中は入力を受け付けず、スキップもありません（仮）。`prefers-reduced-motion` では短い暗転だけで切り替えます。

位置が変わるのは暗転の切れ目の1回だけで、きっぷは保存しません。演出中に再読み込みすると、発車前ならホーム、到着後なら到着駅の整合した状態に戻り、その間の所持品・所持金は変わりません。上り・下りは路線の駅順（増える向き＝下り）で決め、下りは右向きに発車します（暫定）。現在の駅にはホームが1つしかなく、両方向を兼ねます。隣町の駅には改札の操作対象がまだ無く、のりばの看板が改札を兼ねます（暫定）。

## 構造と保存

`world/railway.ts` は駅・路線と、到達性検証用の有向辺を提供します。`travel/network.ts` は既存駅の `STATION_ACCESS` と暫定の隣町駅を参照します。街を増やすときはエリアと駅のデータを追加し、路線の駅一覧に登録します。列車の移動を自動ポータルとして表現しません。

`travel/stations.ts` が駅の改札・のりばのデータを1か所で読み、`travel/session.ts` はきっぷ・乗車・到着の状態を検証し、`travel/ride.ts` が演出の時間割（到着の確定は1回）、`travel/scene.ts` が演出の描画、`travel/panel.ts` が操作画面を担当します。共有側の配線では到着時に通常のエリア変更通知・入力解除・保存を行う案です。現行mainの保存対象は位置・向き・外見です。所持品、所持金、人生履歴、スマホの状態はそれらを持つ統合版で別途保持を確かめます。

## 現在の確認状況

専用の状態・路線・隣町の単体試験では、位置外や無効な到着先からの移動拒否と明示確認を検証しています。#35の実駅を含むworldに隣町をテスト時だけ追加し、鉄道辺による到達性、確認乗車・帰路と位置・外見の保存再読込を確認しています。通常ゲームへの隣町登録・共有入力の接続、実画面の往復・操作性は配線版で検証します。利用者の実画面での確認前に完成扱いせず、PRも作成しません。

配線版が用意できた後、親がsandbox外で実行する例です。ブラウザは独立した一時コンテキストを使います。

```sh
cd game
SLG_URL=http://127.0.0.1:5207 SLG_SHOTS=/private/tmp/slg-audit/train-travel-e2e \
  node scripts/e2e-train-travel.mjs
```

実際の開発サーバーのポートは実行前に確認します。E2Eは元の町から駅へ実際に歩き、改札・乗車・発車・到着・隣町探索・帰路・演出中の再読み込み・動きを減らす設定を確認し、`SLG_VIDEO` を指定すると録画も保存します。1280×800・390×844・844×390の画像を出力します。
