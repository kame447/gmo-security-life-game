# ゲーム内のローカルセーブ

[Issue #20](https://github.com/kame447/gmo-security-life-game/issues/20) の実装候補。利用者の実画面レビュー前なので、PR は作成しない。AWS は使わない。

## 操作

右上の「セーブ」から、手動保存・「つづきから」・「はじめから」を選ぶ。同じブラウザ・同じオリジンで開き直すと、既存の通常保存から自動復帰する。仮オープニングの3案は起動に接続しない。

- **セーブ**: 位置、外見、所持金、バッグとホットバーの配置・選択、スマホの所持・残量・会話と人生イベントの数値・目印・履歴を、既存 v1 のキーへまとめて保存する。全体の生成と`setItem`が成功し、lifeも保護による部分保存でない場合だけ「セーブしました」を表示する。
- **つづきから**: 確認してからページを再読込し、保存済みデータで Game と各 UI を作り直す。確認を戻れば、現在の未保存のゲーム状態を保つ。
- **はじめから**: 「はじめから遊ぶと、今の進行は上書きされます」と確認する。現在の保存文字列を退避してから、新しい Game の初期状態を保存し、再読込する。新規保存には旧 life・未知欄・旧配置を引き継がない。取消・保存失敗なら現在のゲームを続けられる。
- **もどる / Esc**: 確認画面からメニューへ、メニューから探索へ戻る。Tab・矢印で選択、Enter・Space・Z で決定できる。確認画面は「もどる」に初期フォーカスを置く。

既存の位置だけを戻す操作は、新規ゲームと区別して専用プレビューで「スタート地点へ」と表示する。資産・外見・スマホを保持する動作と ID は従来どおり。

## 自動保存と切替の順序

通常の定期保存、pagehide、visibilitychange、エリア移動、スマホ変更、外見確定、バッグと購入の保存は同じ `LocalSaveSession.save` を通す。メニュー・確認中は自動書込を保留し、メニュー内の明示的な保存だけを許可する。外見の選択途中では、確定済みの外見を保存する従来の扱いを保つ。

「つづきから」と新規開始が成功したら、再読込の前に `isSwitching` を立てる。旧ページの pagehide が、これから復帰する保存を未保存の状態で上書きしないようにする。旧セッションの pending は新しい writer へ持ち越さない。オートセーブの周期や購入の資産更新は変更しない。

## 失敗と保護

容量不足・保存領域への拒否・不正なデータを成功として表示しない。手動保存の失敗はパネルに、閉じている間の自動保存の失敗は小さな通知で示す。保存先が使える状態へ戻ったら「セーブ」をもう一度押し、現在の状態を保存できる。

起動時に旧保存を読めなかった場合は、探索を続けられる一方、自動保存と通常の手動保存でその旧保存を置き換えない。明示的な新規開始では、旧文字列を退避できた場合だけ保存を切り替える。起動時のアクセス拒否が回復し、メニューを開いた時点で保存領域が空と確認できた場合は、現在のメモリ内の進捗をそのまま保存できる。読み取れる既存保存があれば「つづきから」で復帰する。

新規開始の退避先は、通常キーに `.previous` を付けた一世代とする。新規開始を再度確認した場合だけ、その時点の現在保存で退避を更新する。通常保存・復帰・取消では退避を変更しない。退避または本保存の書込に失敗した場合は、旧主キーを保持し、操作中の Game を取り替えない。失敗した新規 DTO の pending を通常の writer に渡さない。

この退避は内部の保護用で、プレイヤー用の復元画面は今回含まない。そのため新規開始の確認文では、旧進行を通常画面から選んで続けられるとは案内しない。既存の `.protected`（保存安全性で使う退避）にも触れない。

レビュー用 `review=1` は、通常保存の読込・書込を行わず、セーブパネルも追加しない。

## 実装と検証

| 場所 | 責務 |
| --- | --- |
| `game/src/app/local-save-session.ts` | 自動保存の保留、成否、復帰前の停止、明示的新規開始 |
| `game/src/ui/local-save-panel.ts` と CSS | 操作、確認、失敗表示、フォーカスと入力隔離 |
| `game/src/app/save-store.ts` | 既存 v1 の保存・読込と JSON 検証、未知欄保持 |
| `game/tests/local-save-session.test.ts` | 保存復帰、取消、全入口の保留、拒否・容量、新規失敗後の保全、レビュー隔離 |

独立実装は `feat/local-save-gameplay`（45e1d06 基点）で管理する。PR #54/#55 と重なる入口は、利用者の指定した `preview/local-save-combined` にだけ接続し、既存 PR・main のソースを変更しない。プレビューにはレビュー済みのバッグ・買い物、既存スマホを保持する。

保存先は同じ v1 のまま。既存の save-api 契約の新しい封筒・リビジョン・認証をローカル UI へ追加しない。構造の検証には既存の保存層を使い、必要なバイト上限はその引数へ渡せる。ローカル独自の数値上限は作らない。

バッグの codec が layout を正規化する構成では、保存 codec は layout の既知4欄と未知のメタデータを分けて保持する。バッグをまだ持たない旧構成では、layout 全体を不透明に保持する。通常の保存で追加メタデータを落とさず、明示的新規開始でだけ旧欄を引き継がない。

人生イベントの接続候補 `feat/life-local-save` は、Gameが持つアダプタのstateをDirectorと共有し、確定済みの進行を保存・復元する。旧セーブには空のlifeを追加する。未来版や部分破損lifeは元のJSONを保ち、他欄の保存は続けるが、`protected-life` の失敗通知として扱う。生成自体が失敗した場合は全体を書き込まない。確認した新規開始では空のlifeを使い、旧進行を引き継がない。詳細と未決定事項は [人生イベントの保存](life-save.md)。UI の採用、PR 作成と main への統合は、利用者のプレビュー確認後に行う。
