# 全店舗の買い物とスマホ通販（ローカル確認用）

2026-11-28の「残りの項目をすべてローカル実装し、承認直前まで進める」という指示に対応する実装。対象は既存 Issue #21・#33・#73・#79 と序章の自転車購入。既存 PR #80 のWeb検索をローカルで取り込み、mainへのマージ・push・新規PR作成はしていない。

## 店内の買い物

コンビニ・八百屋・本屋・駄菓子屋・パン屋・カフェ・薬局の7店を、既存 `STORE_CONTACTS` の店員と購入画面へ接続した。青果、文庫本、飲み物、サンドイッチ、絆創膏、マスクを持ち物定義へ追加した。価格と品ぞろえはレビュー用の仮値で、正式な採用を意味しない。使用・消費・回復効果は追加していない。

購入はこれまでと同じ確認画面を経由し、共通の原子的な資産更新APIで所持金と品物を同時に変える。取消・残高不足・数量上限で資産は変わらない。既存セーブの持ち物・スマホ・既読履歴を維持する。

確認用URLは `?review=1&shopReview=konbini`。末尾は `greengrocer`、`bookstore`、`candy`、`bakery`、`cafe`、`pharmacy` に置き換えられる。従来の `shopReview=1` はコンビニとして維持する。すべて一時セッションで通常セーブを読み書きしない。

## 自転車の通販

お使いを終えて母へ報告すると、「お母さん」のメッセージに購入予算と候補URLが3件届く。各URLから商品ページを開き、会社案内や購入条件まで確認して、戻る操作で元のトークへ戻れる。Webでの検索も引き続き使える。画面に出す住所や連絡先はゲーム内設定で、外部サイトや現実の支払い先へ移動しない。

購入予算は母から預かった専用の20,000円。通常の財布とは分け、注文確認画面に価格と予算の残額を出す。19,800円の店は注文でき、24,800円の店は予算超過として注文できない。12,800円の偽サイトを選んだ場合も既存の学習イベントへつながり、母に相談して自転車を入手する。結果・被害・評価は既存の序章と同じ。正規購入の残額200円は財布へ戻り、偽サイト側の残額は町の店で買い直すために使われる。

「注文へ進む」だけでは確定しない。「戻る」で取消でき、「注文を確定する」で一度だけ反映する。スマホを閉じると注文の結果と到着の会話が続き、中学生のステージへ進む。注文の解放状態は省略可能な `story.bikeOrderReady` に保存し、古いセーブを壊さない。重複注文と未解放の注文は受け付けない。

確認用URLは `?review=1&bicycleReview=1`。お使い報告後の一時状態で、3件のURLが届いた母とのトークから始まる。再読み込みすると注文前へ戻る。通常の序章からの進行は `?story=1` の新規セッションで確認できる。

## メールからWebへ

メールのリンクを選ぶと実際のアドレスを表示し、「Webで開く」でゲーム内ページへ移る。ページ内リンクをたどってから戻ると、その履歴を戻り、最後に元のメールへ戻る。受信メールに存在しないリンク、外部の実在ドメイン、通信残量がない状態は受け付けない。表示文言と実際の行き先を別に保持する既存の設計を維持した。

## 検証

`tests/local-commerce.test.ts` は全店の店員接続・購入と保存復帰、母への報告前後、予算超過、注文の一回性、偽サイトの分岐、通信枯渇、メールとWebを往復する履歴を扱う。`scripts/e2e-local-commerce.mjs` はPCとスマホで実際の注文確認、取消、購入、保存隔離、7店の購入、リンク往復を確認して画面を撮る。
