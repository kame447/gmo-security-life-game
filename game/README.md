# 幼少期マップ探索プロトタイプ

[Issue #7](https://github.com/kame447/gmo-security-life-game/issues/7) の探索基盤を確認するブラウザ用プロトタイプです。TypeScript・Vite・Canvas 2D 標準APIを使います。数値や技術構成は [判断記録 0003](../docs/decisions/0003-map-prototype-canvas2d.md) の提案／要検証であり、本採用の決定ではありません。

## 必要環境と起動

Node.js 24 と npm、Canvas 2D に対応したブラウザを使用します。CI も Node.js 24 で実行します。対象ブラウザ・端末の正式なサポート範囲と性能基準は未決定です。

リポジトリのルートから以下を実行します。

```sh
cd game
npm install
npm run dev -- --host 127.0.0.1
```

ターミナルに表示されるローカルURLをブラウザで開きます（通常は `http://127.0.0.1:5173`）。開発サーバーはブラウザを自動で開きません。

今回の検証では Codex サンドボックス内で起動した開発サーバーがファイル変更を反映しませんでした。変更後のブラウザ検証に使う開発サーバーは、サンドボックス外で起動します。

既存の npm キャッシュの所有権などにより `EPERM` が発生する場合は、`npm install --cache /private/tmp/slg-npm-cache` のように書き込み可能な別ディレクトリを指定します。

```sh
npm run build
npm test
```

`build` は TypeScript の型検査後に `dist/` へ出力し、`test` は Vitest を Node 環境で実行します。CI は `game/` 内で `npm ci` → `npm run build` → `npm test` を実行します。

## 操作

| 操作 | キー・画面上の操作 |
| --- | --- |
| 歩く | 矢印キー／WASD（最後に押した方向を優先、4方向） |
| 走る | Shift を押しながら移動 |
| 調べる・話す・会話を進める | Z／Space／Enter、会話欄のクリック |
| 建物へ出入りする | 自宅・校舎・コンビニの出入口へ歩く |
| タッチ操作 | 「タッチそうさ」で表示を切り替え、方向ボタンと A を使う |
| 外見を変更する | 「みため」を開く（会話中は開けない） |
| 開始地点へ戻す | 「さいしょから」 |

会話中は移動を停止します。ウィンドウからフォーカスが外れると入力を解除します。キーボードが反応しない場合はマップ画面をクリックしてください。

「みため」では「かたち」「かみがた」「かみのいろ」「ふく」「ふくのいろ」を変更できます。上下／W・Sで項目、左右／A・Dで選択肢を切り替え、Z／Space／Enterまたは「けってい」で保存します。Escまたは「もどす」で開く前の外見に戻します。各項目の◀▶ボタンはクリック・タッチでも操作できます。パネル中は移動を停止し、プレビューと画面上の主人公へその場で反映します。「さいしょから」で位置を戻しても外見は保持します。選択肢とこの振る舞いはプロトタイプでの提案／要検証です。

| マップ上の印 | 意味 |
| --- | --- |
| 出入口の矢印 | 入れる自宅・校舎・コンビニの入口、または屋内の出口 |
| 近くの対象の吹き出し | 話す・調べる対象。対象の方を向いて決定キーを押す |
| 印のない背景の住宅など | 外観と衝突判定のみで、内部への出入りはできない |

屋内は画面より小さい場合に中央へ表示し、壁の外側を黒く塗ります。出入りでは短い黒からのフェードインを使います。

位置・向き・エリア・年代差分ID・主人公の外見をブラウザの localStorage（`slg-map-save-v1`）へ定期保存します。同じブラウザ・同じオリジンで開くと復帰します。不正な位置などは検証で除外し、開始地点から再開します。外見のない旧セーブは既定の外見で復帰し、一部の外見項目が不正ならその項目だけ既定値に戻します。保存が利用できない環境でも探索は続けられます。会話進行・イベント履歴・人生の状態の保存は含みません。

## ディレクトリ構成とデータ契約

| 配置 | 責務 |
| --- | --- |
| `src/core/types.ts` | エリア・施設・街区・配置物・出入口・インタラクション・年代差分・通知・保存の型 |
| `src/core/coords.ts` | タイル・チャンク・ピクセルの変換と向き |
| `src/core/appearance.ts` | 外見の選択肢・既定値・項目ごとの検証・キャッシュキー |
| `src/world/` | マップの構造化データ、地面、年代差分、組み立てと検証 |
| `src/engine/` | 移動・衝突・遷移・会話・通知・保存内容の検証（DOM 非依存） |
| `src/render/` | Canvas 2D 描画、地面・スプライトのコード生成、カメラとキャッシュ |
| `src/main.ts` | 入力、画面UI、保存、描画ループの接続 |
| `tests/` | データと探索処理の回帰テスト |
| `index.html` | Canvas・会話欄・操作UI |

`AreaDef` は地面のタイルID配列と配置物・出入口・インタラクションを保持します。`DistrictDef` はエリア内の街区で、エリア遷移の単位とは別です。施設は `FacilityDef.interior` で `full`（内部あり）、`interaction`（簡易インタラクション）、`background`（背景のみ）を区別します。

`PortalDef` は遷移元タイルと遷移先エリア・タイル・向きを保持します。座標は北西原点、東が +X、南が +Y。マップの配置はタイル単位、プレイヤーの位置・保存座標は足元基準点のピクセル単位です。タイルは16px、チャンクは16タイル、町は128×80タイルを仮置きしています。

`VariantDef` は施設状態、出入口・インタラクションの無効化、インタラクションの追加を基底マップから分けます。`MapEvent`／`MapEventSink` は探索からの通知と会話の受け口であり、イベント条件評価や人生の時間進行は扱いません。

`src/world/index.ts` の `buildWorld()` が地面と配置物から衝突・出入口・インタラクションの索引を組み立てます。`validateWorld()` は重複ID、範囲外、未知の施設・遷移先、通行不可の開始点・遷移先、開始点から到達できない出入口や調査対象を検出し、問題の文字列配列を返します。`findPath()` はタイル単位の4近傍BFS、`LANDMARKS` はテスト用の名前付き地点です。

外見は `PlayerAppearance` として探索通知から分けて保持します。主人公の `playerSprite()` は4方向・立ち／歩行の表示を外見ごとにコード生成し、NPCとは別の上限付きキャッシュを使います。外見変更によって能力・会話・イベント結果は変えません。

## 検証

2026-11-12の最終ビルドは成功、単体テストは3ファイル・54件すべて成功しました。ブラウザ実行担当の最終E2Eログでも `SUMMARY` 13項目すべてPASS、終了コード0を確認しました。外見UIと移動停止、主人公の画素変化とNPC表示の維持、外見の保存・開始地点復帰後の保持・取消、自宅・教室・コンビニの往復と会話、屋内の黒とフェード、壁の遮蔽・整数カメラ、各種衝突、スクリーンショット、位置復元・フォーカス離脱時の入力解除が対象で、ページ・コンソールエラーは0件でした。

性能スクリプトの全経路検証は途中中断のため未完了です。直線歩行の切り分け計測と、E2Eの機能検証の成功を、全経路・走行・遷移の連続性の合格や実ディスプレイの60Hzでの体感確認とは扱いません。

`tests/appearance.test.ts` は外見の選択肢・既定値・項目ごとの正規化と、全組み合わせのキャッシュキーを検証します。`tests/engine.test.ts` では外見を含む保存・復帰、外見を持たない旧セーブの互換、開始地点へ戻した後の外見保持、外見を変えても移動・衝突・通知が変わらないことも確認します。

`tests/world.test.ts` はマップのID・参照・範囲・到達性、主要地点への経路、橋・踏切の通行、屋内外の復帰位置、建物の玄関前・庭の門・商店街歩道の通行、年代差分の適用、チャンクID、生成の決定性、不正データの検出を検証します。

`tests/engine.test.ts` は速度、衝突・マップ端、角の補正、会話中の移動停止、通知、保存・復帰を検証します。実マップについては自宅から学校・駅・公園への経路を `Game.update()` で歩き、自宅・教室・コンビニの出入口を往復して屋外の復帰位置・向きを確認します。

時間刻みを変えた歩行・走行距離、長い更新でも壁や入口を飛び越えないこと、1描画フレーム内で複数回更新する際の出入口通過後の移動・会話停止・端通知も単体テストに含みます。

`scripts/e2e.mjs` は開発サーバーに対してヘッドレス Chromium を使う手動実行用の検証です。サーバー起動後、別のターミナルの `game/` 内で実行します。

機能E2Eは `--disable-gpu-vsync --disable-frame-rate-limit` で実行します。外見の画素変化とNPC表示の維持、保存・取消、パネル中の移動停止、3施設の往復と会話、屋内の黒背景・壁の遮蔽・フェード・整数カメラを検査します。既定ヘッドレスでの低フレームレート耐性は `test:perf` が受け持ちます。

```sh
npm run test:e2e
```

事前にPlaywrightのChromiumが利用でき、ヘッドレスブラウザを起動できる環境が必要です。今回の Codex サンドボックス内では `MachPort Permission denied` により起動できず、ブラウザ実行は別の実行環境で行います。これは `npm test` や今回追加したCIジョブには含みません。

`SLG_URL` で検証先URL、`SLG_SHOTS` でスクリーンショット保存先を指定できます。ブラウザを別の場所へインストールした場合は `PLAYWRIGHT_BROWSERS_PATH` をそのディレクトリに合わせます。

macOS の既定の保存先 `~/Library/Caches/ms-playwright` に書き込めない環境では、書き込み可能な保存先を指定してブラウザを入手し、実行時にも同じ環境変数を指定します。今回のローカル検証では `/private/tmp/slg-browsers` を使用します。

```sh
PLAYWRIGHT_BROWSERS_PATH=/private/tmp/slg-browsers npx playwright install chromium
PLAYWRIGHT_BROWSERS_PATH=/private/tmp/slg-browsers npm run test:e2e
```

`scripts/perf.mjs` は6つの屋外経路、歩行・走行の実時間速度、自宅・教室・コンビニの往復を実キー入力で検査します。既定ヘッドレスとフレーム制限解除の2モードを実行し、フレーム間隔、更新・描画時間、速度、移動・カメラの連続性を集計します。

```sh
PLAYWRIGHT_BROWSERS_PATH=/private/tmp/slg-browsers SLG_OUT=/private/tmp/slg-perf npm run test:perf
```

`SLG_OUT` を指定すると `perf-result.json`・動画・連続画像を保存し、各シナリオ終了時にも `scenario-result.json` を保存します。指定しなければファイルは保存しません。`SLG_URL`、`SLG_VIEWPORT`（例 `1280x720`）、`SLG_DPR`、`SLG_MACHINE` で検証先と環境を指定できます。`SLG_CHANNEL=chrome` はインストール済みChrome、`SLG_EXECUTABLE` は別のブラウザ実行ファイルを指定します。`npm run test:perf -- --matrix` はChromium／Chromeと1280×720／640×360の組み合わせを実行するため、両ブラウザが必要です。

両スクリプトは最後に `SUMMARY` 行を出力します。性能検査は連続性違反や候補の速度許容差超過で失敗し、フレーム時間だけの超過や1フレーム16px超の移動は警告として扱います。`test:perf` も今回のCIジョブには含めません。

## 移動とスクロールの初回計測（2026-11-12）

ユーザーの独立監査から共有された修正前の結果です。環境は Playwright のヘッドレス Chromium 158.0.8127.18、1280×720、DPR 1、ローカル開発サーバー。衝突のない直線で右方向を4.5秒押した計測です。

| 項目 | 初回結果（修正前） |
| --- | --- |
| rAFサンプル | 61（間隔の集計は60） |
| フレーム間隔の平均／中央値 | 75.0／100ms |
| p95／p99／最大 | 116.7／150／150ms |
| 33ms超 | 41/60（68.3%） |
| 移動距離／実時間あたり速度 | 166.8px／約37px毎秒（提案値72px毎秒） |
| ページエラー | 0 |

当時のループが1フレームの `dt` を50msで切り捨てていたため、50msを超えるフレームでは実時間あたりの移動速度が落ちます。修正として `src/main.ts` に経過時間の蓄積と1/120秒の固定刻み、蓄積上限250msを仮置きし、複数回更新した後に1回描画する構成を追加しています。刻み・上限はプロトタイプでの提案／要検証です。

この環境では操作なしでも約100〜117ms間隔で、viewport縮小・ブラウザ変更・GPU指定でも同様でした。一方、既定条件の更新・描画時間は短く、フレーム制限を外すと間隔が数msへ変わります。実行担当の切り分けでは、約10Hzの間隔はこのMacのヘッドレス実行によるrAFの間引きと判断しています。描画処理の重さが約100msの主因であることを示す結果ではありません。

固定刻み化後は既定ヘッドレスの直線歩行でも71.5px毎秒となり、dt切り捨てによる速度低下はこの条件で改善しました。ただし、フレーム制限解除の値は処理時間と連続性を調べる条件であり、実ディスプレイの60Hz垂直同期で滑らかに見えることの達成値にはしません。

全経路・走行・屋内外遷移の連続性を確認する `test:perf` は途中中断のため未完了です。中断ログには一部経路のFAILがありました。検査担当のNode再現では、低fps時の経路到着許容と壁接触時の距離減少の判定に問題があり、計測スクリプトを修正しました。修正後の6経路×100／116.7／150msの18再生は到達・連続性違反0との報告ですが、元のブラウザフレーム記録が残っていないため、当初のFAILと完全に同じ原因だったとは断定しません。ブラウザでの完走確認と、実ディスプレイの60Hz垂直同期での体感は引き続き未検証です。評価閾値（実時間速度の許容差、実測リフレッシュ間隔に対するp95、連続性違反件数など）は候補であり、合意済みの性能基準ではありません。
